# 实验设置、公平性与可复现性（中文初稿）

## 实验环境与协议

实验使用 Helix 的离散事件仿真器评估 LLaMA-70B 流水线推理，不涉及真实 GPU 推理或广域网部署。我们分别测试单集群和三集群拓扑；每个拓扑包含 24 台异构设备（4 台 A100、8 台 L4、12 台 T4），沿用 Helix artifact 的机器画像、物理链路配置和 Azure Conversation 请求长度数据。在线官方负载的目标到达强度分别为 700 和 320 token/s。每次实验使用 1800 秒固定测量窗口、零预热，窗口结束时停止仿真，不排空仍在途的请求。

完整系统对照使用 Helix 官方 ILP 放置及 MaxFlow 在线调度作为基线，RCAPS 使用自己的放置和队列感知调度。两方法在同一场景和随机种子下共享请求生成参数与轨迹；评测脚本核对 `trace_sha256`、到达数、负载、预热和窗口长度。两者的逻辑层放置及由此生成的合法传输边可以不同，因为它们正是放置算法的输出。控制变量实验则固定一方的放置文件及仿真配置，只改变另一方的调度组件，或固定调度器只改变放置方案。

## 指标与截尾

输出吞吐为测量窗口内完成的输出 token 数除以窗口时长。首 token 时延（TTFT）从请求到达到首个解码输出完成计时；每个请求的 token 间隔（TPOT）为其连续解码输出完成时间差的平均值。P95 在窗口内获得相应样本的请求之间计算。窗口末尚未得到首 token 或足够多解码输出的请求不进入相应 P95，因此本文始终同时报告到达数、TTFT／TPOT 样本数、窗口内完成率和末尾积压。新增重复实验还保存逐请求样本，对两方法均观察到指标的同一请求集合重算 P95，作为截尾敏感性检查；该共同集合统计仍不能代表未观察到输出的请求。

## 统计与复现

随机种子而非单个请求是配对统计的重复单位。已有种子 0、1、2 的逐种子变化以均值和样本标准差描述，其中种子 1 曾参与开发调参，故不作为独立盲测证据。新增实验预先指定种子 20–29 为独立复验集，记录六个预定义场景／指标单元的配对效应、95% t 区间和单侧精确符号检验，并在显著性判断中作 Holm 校正。区间仅刻画这些仿真轨迹的种子波动，不包含真实硬件、网络测量或拓扑抽样的不确定性。

代码、实验入口、布局及论文结果均保存在仓库中。复现记录包括代码提交 SHA、Python／NumPy／Gurobi 版本、输入数据和配置的 SHA-256、请求轨迹 SHA-256、实验命令、种子、失败日志和结果 JSON。`python -m benchmarks.manifest` 生成输入清单；`python -m benchmarks.run` 执行或恢复实验；`python -m benchmarks.compare` 检查成对运行及共同请求集合；`python -m benchmarks.paired_stats` 生成逐种子统计。所有失败的对照保留失败状态，绝不以中断前的部分窗口数值补齐完整运行。
