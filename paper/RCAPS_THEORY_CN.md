# RCAPS：系统模型与方法设计

## 3 系统模型与问题定义

### 3.1 异构推理资源与请求模型

本文研究模型分布于多台异构 GPU、计算与通信资源由多个推理会话共享的服务环境。模型由按顺序执行的 $L$ 个层构成，层编号为 $0,\ldots,L-1$。物理资源表示为有向图 $\mathcal G_{\mathrm{phy}}=(\mathcal V\cup\{\sigma,\omega\},\mathcal E_{\mathrm{phy}})$，其中，$\mathcal V$ 为 GPU 集合，$\sigma$ 和 $\omega$ 分别为请求入口与输出端。对于 GPU $i$，记可驻留的最大层数为 $c_i$，发送与接收网卡带宽分别为 $u_i^{\mathrm{out}}$ 和 $u_i^{\mathrm{in}}$。入口与输出端的网卡容量沿用相应方向的带宽符号。物理连接 $(i,j)$ 的标称带宽与传播时延分别记为 $B_{ij}$ 和 $\delta_{ij}$。同一节点上的不同连接共享相应方向的网卡资源。

以 $f^P_{i,\ell}(n)$ 表示 GPU $i$ 在第 $\ell$ 层处理 $n$ 个 Prompt token 的画像服务时间，以 $f^D_{i,\ell}(m)$ 表示处理 $m$ 个 Decode token 的画像服务时间。画像随设备类型、执行阶段和批量规模变化。RCAPS 通过画像插值获得候选执行区间的服务代价，而不使用统一的设备算力常数替代上述差异。

请求 $r$ 在时刻 $a_r$ 到达，输入长度为 $n_r$。其执行包含一次 Prompt 阶段和随后逐步生成输出 token 的 Decode 阶段。RCAPS 在 Prompt 从入口发出前选择完整执行路径，后续 Decode 沿用该路径及对应层区间，使会话的 KV 状态保留在原执行节点。在线选路使用已知输入长度和当前资源状态，不依赖请求未来输出长度。

本文采用按层划分的流水执行模型。每个参与部署的 GPU 驻留一个连续层区间；同一模型段可以部署多个副本，不同副本使用互不重叠的 GPU 集合。部署决定模型权重与会话可用的执行结构，运行时调度决定请求何时使用这些资源。层驻留容量与会话 KV 占用分别约束部署可行性和运行时并发，两者在建模中予以区分。

### 3.2 层兼容执行空间

设部署方案为 $x$，参与部署的 GPU 集合为 $\mathcal V_x\subseteq\mathcal V$。GPU $i$ 驻留的层区间记为 $I_i=[a_i,b_i)$，并满足

$$
0\leq a_i<b_i\leq L,\qquad b_i-a_i\leq c_i.
\tag{1}
$$

以已完成层边界 $h$ 描述请求的模型进度，即请求已经执行层区间 $[0,h)$。请求能够进入 GPU $j$ 的条件为 $a_j\leq h<b_j$；进入后仅执行尚未完成的区间 $[h,b_j)$。因此，上游 GPU $i$ 与下游 GPU $j$ 之间的合法转换同时满足物理连接约束与层进度约束：

$$
(i,j)\in\mathcal E_{\mathrm{full}}(x)
\iff
(i,j)\in\mathcal E_{\mathrm{phy}},\quad
a_j\leq b_i<b_j,
\qquad i,j\in\mathcal V_x.
\tag{2}
$$

入口边连接具有物理入口连接且 $a_j=0$ 的 GPU，输出边连接具有物理输出连接且 $b_i=L$ 的 GPU。由这些边构成的图记为 $\mathcal G_{\mathrm{full}}(x)$。物理网络可以包含环，但式（2）要求每次 GPU 转换均严格增加已完成层边界，因而执行图具有有向无环结构。

层兼容关系允许相邻节点驻留区间重叠。例如，上游驻留 $[0,8)$、下游驻留 $[4,12)$ 时，请求在完成前八层后，可在下游继续执行 $[8,12)$。驻留重叠提供了路径切换的可能性，执行区间则仍然连续且不重复。该表示将“GPU 存储哪些层”与“某一请求在该 GPU 上实际执行哪些层”区分开来，使跨副本连接可以在同一合法性规则下描述。

记 $\mathcal P(\mathcal E)$ 为边集 $\mathcal E$ 所诱导的入口至输出端完整路径集合。有效部署要求 $\mathcal P(\mathcal E_{\mathrm{full}}(x))\neq\varnothing$，并进一步检查部署所指定的各条规范副本链均具有前向与后向可达性。层兼容执行图由此提供统一的执行合法性接口：放置搜索产生的部署、空间准入选择的边以及在线路由输出的路径均须服从同一层兼容关系。

### 3.3 决策对象与性能目标

RCAPS 面向的决策包括部署结构 $x$、开放给在线路由的边集 $\mathcal E_{\mathrm{adm}}$、会话路径 $p_r$ 和 Prompt 传输的资源让出时机。其结构约束可以写为

$$
x\in\mathcal X,\qquad
\mathcal E_{\mathrm{can}}(x)\subseteq
\mathcal E_{\mathrm{adm}}\subseteq
\mathcal E_{\mathrm{full}}(x),\qquad
p_r\in\mathcal P(\mathcal E_{\mathrm{adm}}),
\tag{3}
$$

其中，$\mathcal X$ 为满足层容量、副本覆盖、物理连接与可达性检查的部署集合，$\mathcal E_{\mathrm{can}}$ 为由部署直接指定的规范连接集合。

这些决策通过不同途径影响服务表现。放置决定可用副本与计算分工；路由决定新会话如何分布于既定资源；路径开放范围影响会话分散程度；传输让出决定长消息连续占用链路和网卡的时间。因而，减少某条路径上的等待、增大 Decode 批量和降低总 GPU 工作量并非等价目标。例如，分散会话可能缩短当前队列，却同时减小后续 Decode 的可合批规模。

本文以首 token 延迟、请求级 Decode 间隔、输出吞吐、请求完成率、窗口末端积压及单位输出 token 的 GPU 忙碌时间共同评价系统。对于一个已观测到多个输出 token 的请求，先计算其相邻输出 token 时间间隔的均值，再统计该请求级指标的分位数。该口径与对全部单 token 间隔直接取分位数不同。GPU 忙碌时间反映计算工作量，其解释须同时考虑已完成工作与未完成请求。

RCAPS 采用分层决策：离线阶段使用静态代理目标选择放置，在线阶段使用当前状态下的可加代价选择会话路径，执行阶段通过路径准入和传输分块调节资源使用。离线与在线目标分别服务于相应决策时间尺度；最终服务指标由共享资源上的完整执行过程决定。

## 4 RCAPS 方法设计

RCAPS 以层兼容执行图为统一表示，通过分段共享与复制放置构建可执行路径，利用实时资源感知的会话选路分配请求，并通过时空执行整形调节路径开放范围与长 Prompt 传输占用。其中，时空执行整形由空间准入和传输分块组成，分别作用于会话路径选择之前和通信执行过程中。图 1 给出各部分的关系：放置方案导出完整层兼容图，空间准入据此构造准入图，在线路由在准入图内选择会话路径，执行器沿该路径完成计算，并在符合条件的 Prompt 传输块边界让出资源。

> **图 1 图位：RCAPS 整体架构与决策关系。**

**图 1. RCAPS 的整体执行流程。** 放置搜索根据物理拓扑、设备容量与服务画像确定层放置，并导出层兼容执行图。空间准入保留规范连接并选择性开放跨副本边。在线路由读取 GPU、链路及活跃会话状态，在准入图内选择固定会话路径。执行器按路径完成计算与传输，传输分块在合格的 Prompt 传输块边界释放资源。空间准入位于选路之前，传输分块位于传输执行内部。

### 4.1 异构资源上的分段共享与复制放置

#### 4.1.1 放置结构与可行性

放置搜索将模型划分为 $K$ 个连续段，分段边界满足

$$
0=\ell_0<\ell_1<\cdots<\ell_K=L.
\tag{4}
$$

第 $k$ 段对应 $[\ell_{k-1},\ell_k)$，包含 $w_k$ 条副本链。每条副本链由若干 GPU 顺序组成，各 GPU 承担该段的一部分连续层，链内层区间首尾衔接并完整覆盖该段。第一段设置为单副本共享段，后续各段允许采用不同副本数，使执行结构可以在段边界处分支或汇合。当前搜索空间取 $K\in\{2,3\}$，每段副本数不超过四个。

放置检查包含以下约束：每条副本链完整覆盖所属模型段；GPU 不跨副本重复分配；每个 GPU 的层数不超过容量且部署后具有正 KV 容量；副本内部存在相应物理连接；所有副本均可从入口到达并能继续到达输出端。未分配的 GPU 可以保持空闲。通过上述检查的放置再依据层兼容关系导出完整执行图，从而为在线路由提供超出规范副本链的合法连接。

这类放置直接调节不同模型段的复制程度。副本数增加时，系统可以将会话分散到更多计算资源，也需要驻留更多层副本。设第 $k$ 段长度为 $d_k=\ell_k-\ell_{k-1}$，则总层副本数为

$$
C_{\mathrm{layer}}(x)=\sum_{k=1}^{K}w_kd_k.
\tag{5}
$$

式（5）刻画了改变分段边界与副本宽度对权重驻留规模的影响。因此，不同放置之间的比较既反映路径结构变化，也可能包含复制容量变化。

#### 4.1.2 静态代理目标

放置搜索使用三个静态量评价候选放置：规范路径上的最大 Prompt 服务时间 $T_P(x)$、最大 Decode 服务时间 $T_D(x)$，以及均匀分流假设下的最大资源需求 $D_{\max}(x)$。前两项覆盖规范路径中的 GPU 服务、传输序列化与传播时延。Prompt 以固定代表输入长度 $\bar n$ 评价，Decode 计算以固定代表批量 $\bar m$ 评价。因而，$T_D$ 是放置比较所用的 Decode 代理代价，不是线上请求级 TPOT 的预测值。

对于规范图中的 GPU $i$，记从入口均匀分流至该 GPU 的概率为 $\pi_i$；对于规范连接 $(i,j)$，相应流量概率为 $\pi_{ij}$。分流只发生在实际可达的后继副本之间。以 $t_i^P$、$t_i^D$ 表示 GPU 的 Prompt 与 Decode 服务时间，以 $s_{ij}^P$、$s_{ij}^D$ 表示连接的对应序列化时间，则资源需求定义为

$$
\begin{aligned}
D_i(x)&=\pi_i\bigl(t_i^P+\eta t_i^D\bigr),\\
D_{ij}(x)&=\pi_{ij}\bigl(s_{ij}^P+\eta s_{ij}^D\bigr),\\
D_{\max}(x)&=\max\!\left\{\max_i D_i(x),\max_{(i,j)}D_{ij}(x)\right\}.
\end{aligned}
\tag{6}
$$

其中 $\eta=8$ 为固定 Decode 需求权重。连接需求只累计带宽序列化时间，传播时延进入路径时间而不进入式（6）。静态评估中，入口连接使用 token 载荷，其余规范连接使用 token 与激活载荷之和；Prompt 载荷按 $\bar n$ 缩放，Decode 连接使用一个 token 的载荷。该静态口径与第 4.3 节按当前请求构建的在线传输估计分别定义。

设 $x^{\mathrm{ref}}$ 为共同参考放置，候选方案的归一化目标为

$$
J(x)=0.40\frac{T_P(x)}{T_P(x^{\mathrm{ref}})}
+0.35\frac{T_D(x)}{T_D(x^{\mathrm{ref}})}
+0.25\frac{D_{\max}(x)}{D_{\max}(x^{\mathrm{ref}})}.
\tag{7}
$$

前两项控制规范路径的服务代价，第三项惩罚均匀分流下的资源需求集中。归一化使不同量纲尺度的代理量能够在固定权重下比较。线上路由不要求遵循这里的均匀分流概率，式（7）用于部署筛选。

#### 4.1.3 有界候选搜索

搜索首先枚举离散分段位置与副本宽度组合，按设备容量构造副本所需的 GPU 分组。初始化的分段边界以四层为步长。单边界候选取 $w_2\in\{2,3,4\}$；双边界候选取 $w_2\in\{2,3,4\}$、$w_3\in\{1,2,3,4\}$ 且 $w_2\neq w_3$。分组阶段采用宽度为 64 的束搜索，并允许设备空闲。在满足容量下界后，算法根据物理连接确定链内顺序，再分配各节点承担的层数。候选按副本形状保留多样性，经过低成本排序后进入式（7）的完整评估。

在候选初始化的基础上，局部搜索通过移动分段边界、调整相邻 GPU 的层数、交换链内顺序、移动或交换不同副本的 GPU，以及加入或移除 GPU 构造邻域。每个候选均重新检查完整可行性。重复候选复用已有评分，只有严格改善目标的邻域动作才被接受。

为控制部署开销，搜索先运行至多 500 次新候选评估的共同阶段，再分别对单边界与双边界候选执行至多 500 次新评估的扩展阶段。每个局部搜索起点最多接受 16 次改进。完整搜索保留共同阶段的当前最优方案，因此允许最终结果仍为单边界结构。预算规定的是评估上限；候选耗尽或不存在改善动作时提前停止。

放置搜索输出搜索过程中获得的最优可行方案及其层区间、规范副本结构和合法执行图。有限候选空间与搜索预算使该过程具有明确的部署边界，式（7）的全局最优性不作为算法前提。

### 4.2 保留规范结构的空间准入

#### 4.2.1 路径开放范围

完整层兼容图允许请求在重叠层区间之间转换。更多连接扩大了避开繁忙资源的选择空间，但也可能使会话分散到更多执行序列，改变后续 Decode 的相遇位置与时间。空间准入在保持部署基本可达结构的同时限制这部分额外选择。

首先，从放置 $x$ 中构造规范连接集合 $\mathcal E_{\mathrm{can}}$，包括各段副本的内部链边、入口和输出边，以及相邻模型段副本端点之间存在的合法物理连接。规范图明确保留部署原本提供的完整执行方式。随后，空间准入从非规范合法边中选择与慢规范连接局部相关的高速边。

以 $S$ 表示空间准入控制，给定其带宽阈值 $\theta_S$，慢规范连接集合为

$$
\mathcal E_{\mathrm{slow}}=
\left\{(i,j)\in\mathcal E_{\mathrm{can}}:
i,j\in\mathcal V_x,\ B_{ij}\leq\theta_S\right\}.
\tag{8}
$$

分别记这些连接的起点与终点集合为 $\mathcal A$ 和 $\mathcal B$。选择性开放的额外边为

$$
\mathcal E_{\mathrm{extra}}=
\left\{(i,j)\in\mathcal E_{\mathrm{full}}\setminus\mathcal E_{\mathrm{can}}:
i,j\in\mathcal V_x,\ B_{ij}>\theta_S,
\ i\in\mathcal A\ \lor\ j\in\mathcal B\right\},
\tag{9}
$$

最终准入边集为

$$
\mathcal E_{\mathrm{adm}}=
\mathcal E_{\mathrm{can}}\cup\mathcal E_{\mathrm{extra}}.
\tag{10}
$$

默认 $\theta_S=50{,}000{,}000\ \mathrm{B/s}$，即 50 MB/s。阈值作用于物理链路标称带宽。式（9）为慢规范连接的邻接位置保留部分高速转换机会；每条额外边是否被使用，由在线路由根据当前代价决定。

图 2 示意三种路径空间的关系：规范空间保留部署副本连接，完整空间包含全部层兼容连接，稀疏准入空间在两者之间选择。空间准入在部署初始化时确定边集，运行中不根据队列状态重新调整。这里的准入对象是路径边，请求本身仍进入既定服务流程。

> **图 2 图位：层兼容关系及规范、稀疏与完整路径空间。**

**图 2. 在同一部署上构造不同执行空间。** 节点标注驻留层区间，GPU 之间的连边均满足完成层边界严格递增。规范边保留副本内部链和相邻段的连接，稀疏空间额外开放满足式（9）的高速边，完整空间保留所有合法边。图中示例用于说明边集构造，不表示实验拓扑或测量结果。

#### 4.2.2 空间准入对批量形成的影响

空间准入通过改变可选路径约束会话分布，而不直接指定 Decode 批量。请求最终是否合批仍由到达时刻、上游执行进度、GPU 就绪队列与发送条件共同决定。较集中的执行路径可以增加会话共享后续计算节点和传输跳的机会，但也可能使部分节点与连接承受更集中的等待。因此，空间约束的计算工作收益和延迟收益需要分别评价。

式（10）保留了两种能力：规范连接提供原有部署的可达基础，额外连接提供局部绕行机会。该结构避免将全部非规范连接等同于必要路径，也允许在线路由在保留下来的多个选择之间响应实时资源竞争。

### 4.3 实时资源感知的会话选路

#### 4.3.1 可加路径代价

在线路由在新请求选择路径时刻 $t$ 读取一次资源快照。以 $R_i^G(t)$ 和 $R_{ij}^N(t)$ 分别表示由当前 GPU 工作和网络状态估计的虚拟释放时刻，并定义

$$
W_i^G(t)=\max\{0,R_i^G(t)-t\},\qquad
W_{ij}^N(t)=\max\{0,R_{ij}^N(t)-t\}.
\tag{11}
$$

GPU 快照累计正在执行批次的剩余工作和已进入本地队列的工作；网络快照考虑当前发送、两端网卡占用及已有固定路径请求的待发送工作。虚拟释放量用于表示当前资源竞争，不对未来到达或完整输出序列进行预测。另以 $N_i(t)$ 表示路径经过 GPU $i$ 的活跃会话数，用于描述当前队列之外持续存在的 Decode 服务压力。

请求 $r$ 从已完成边界 $h$ 进入 GPU $j$ 时，Prompt 服务代价为

$$
C^P_j(h,r)=\sum_{\ell=h}^{b_j-1}f^P_{j,\ell}(n_r).
\tag{12}
$$

活跃会话项使用单 token Decode 服务画像：

$$
C^D_j(h)=\kappa\sum_{\ell=h}^{b_j-1}f^D_{j,\ell}(1),\qquad \kappa=2.
\tag{13}
$$

$\kappa$ 与当前仿真执行器的 singleton Decode 服务口径保持一致。$N_j(t)C^D_j(h)$ 表示以单 token 服务为单位的活跃会话代价，后续实际形成的批量由执行器决定。这里不使用典型 Decode 批量的均摊时间替代式（13）。

对连接 $(i,j)$，在线估计采用标称链路和两端网卡上限的最小值

$$
\widehat B_{ij}=\min\{B_{ij},u_i^{\mathrm{out}},u_j^{\mathrm{in}}\},
\qquad
\tau_{ij}(r)=\delta_{ij}+\frac{m_{ij}(r)}{\widehat B_{ij}}.
\tag{14}
$$

其中，入口边与输出边的载荷为 $m_{ij}(r)=z_{\mathrm{tok}}n_r$，GPU 间连接的载荷为 $m_{ij}(r)=(z_{\mathrm{tok}}+z_{\mathrm{act}})n_r$；$z_{\mathrm{tok}}$ 与 $z_{\mathrm{act}}$ 分别为每 token 的 token 数据和激活数据字节数。已有资源竞争通过式（11）加入代价，式（14）不等同于对瞬时可用带宽的直接预测。

由前驱 GPU $i$ 进入 GPU $j$ 的代价定义为

$$
c_{ij}(r,t)=
C^P_j(b_i,r)+W_j^G(t)+N_j(t)C^D_j(b_i)
+W_{ij}^N(t)+\tau_{ij}(r).
\tag{15}
$$

入口转换以 $b_\sigma=0$ 代入，输出转换仅包含对应网络等待与传输时间。各项均以秒为单位。前两类服务项体现新请求及活跃会话的计算代价，等待项体现当前竞争，传输项体现路径本身的通信差异。

#### 4.3.2 层序动态规划

在固定快照下，式（15）对路径可加。记 $F_r(h,i)$ 为到达 GPU $i$、完成边界为 $h$ 时的最小累计代理代价。初始化 $F_r(0,\sigma)=0$，其余状态为正无穷。按 GPU 驻留区间终点递增处理，递推式为

$$
F_r(b_j,j)=
\min_{\substack{(i,j)\in\mathcal E_{\mathrm{adm}}\\a_j\leq b_i<b_j}}
\left\{F_r(b_i,i)+c_{ij}(r,t)\right\}.
\tag{16}
$$

完成全部模型层后，选择

$$
i_r^*\in\arg\min_{\substack{i:\ b_i=L\\(i,\omega)\in\mathcal E_{\mathrm{adm}}}}
\left\{F_r(L,i)+W_{i\omega}^N(t)+\tau_{i\omega}(r)\right\},
\tag{17}
$$

并从终端 GPU $i_r^*$ 沿前驱记录恢复完整路径 $p_r^*$ 及每跳实际执行的层区间。若存在多个同代价候选，则依固定遍历顺序选择。由于进入 GPU $j$ 后均完成至 $b_j$，相同终端状态后续可用的转换相同，保留最小累计代价即可。

**算法 1：资源感知会话选路。** 输入为新请求、部署层区间、准入边集及当前仿真状态，输出为包含实际执行层区间的完整会话路径。

1. 读取 GPU 与网络虚拟释放快照，统计活跃会话数。
2. 按驻留层终点排序 GPU，建立入口状态与前驱记录。
3. 对每个 GPU，检查已到达状态到该 GPU 的准入边，依据式（15）累计代价并保留最优前驱。
4. 在完成边界为 $L$ 的状态中加入输出连接代价，恢复最小代价完整路径。
5. 将路径绑定至会话，后续 Decode 复用相同 GPU 序列与执行区间。

在线路由每次为新会话决策，已有会话不因队列变化而迁移 KV 或重新选路。执行器对已就绪 Decode 给予发送优先级，并将同一传输跳上已就绪的 Decode 合并发送，不设置等待未来请求凑批的定时器。该执行规则与路径绑定共同决定了在线选路后的实际批量形成过程。

### 4.4 Prompt 传输分块与资源让出

#### 4.4.1 连续占用与资源让出

发送优先级只在资源分配时生效。若长 Prompt 已经获得链路及两端网卡带宽，后续就绪的 Decode 仍可能等待该传输释放资源。传输分块在 Prompt 传输内部增加可重新调度的边界，以缩短单次连续序列化占用。

以 $T$ 表示传输分块控制。默认情况下，该控制只作用于标称带宽 $B_{ij}\leq\theta_T$ 的 GPU 间连接，取 $\theta_T=50{,}000{,}000\ \mathrm{B/s}$。入口和输出连接不在分块范围内。设一次 Prompt 激活传输的总载荷为 $M$、块长为 $q$，则块数和各块字节数分别为

$$
H=\left\lceil\frac{M}{q}\right\rceil,\qquad
M_h=\min\{q,M-(h-1)q\},\quad 1\leq h\leq H.
\tag{18}
$$

当前默认块长为 $q=4{,}194{,}304$ B，即 4 MiB。对于 $M\leq q$ 的传输，不产生中间让出边界。

每个非末尾块发送结束时，传输分块释放该传输持有的链路带宽、发送端网卡带宽与接收端网卡带宽，并先触发常规发送调度。已就绪 Decode 由既有调度器选择；随后 Prompt 尝试恢复发送。续传沿用该传输已确定的带宽额度，若连接或任一端网卡暂时无法满足该额度，则保留未发送字节并延后续传。

**算法 2：Prompt 传输分块与续传。** 输入为固定路径上的 Prompt 传输、块长及作用范围，输出为与原传输相同的逻辑载荷交付。

1. 判断连接类型、带宽阈值和载荷长度；不满足分块条件时执行普通传输。
2. 按已分配带宽发送至多 $q$ 字节，记录剩余字节数。
3. 若存在剩余字节，释放链路与两端网卡的带宽额度，先触发普通发送调度，再尝试恢复 Prompt。
4. 若资源不足，保持暂停状态；在后续发送完成事件触发的续传机会中重新检查资源。
5. 重复发送与让出，直至全部字节发送完成，再经过一次原传播时延将请求交付给接收端。

如图 3 所示，传输分块改变的是一次网络传输中可重新分配资源的时机。每个块不触发下游层计算，下游只有在收到完整载荷后才继续执行。分块保留原会话路径和逻辑请求，因此其作用范围是 Prompt 通信的时间组织。

> **图 3 图位：未分块与分块 Prompt 传输的资源占用时序。**

**图 3. Prompt 传输中的块间让出。** 在相同载荷和相同请求就绪条件下，未分块传输持续持有相应带宽额度；分块传输在块结束时释放链路与两端网卡，并给普通调度器处理就绪 Decode 的机会。Prompt 在资源重新可用后续传，接收端在全部字节发送完成并经过一次传播时延后获得完整请求。时间线为机制示意，不编码实测延迟或固定收益比例。

#### 4.4.2 块长与作用范围

块长决定资源重新调度机会的间隔。较小块长增加让出次数，可以更早暴露发送机会，也会增加分块与续传事件数量；较大块长减少事件数量，却保留更长的连续占用。当前实现采用固定块长，并将作用范围限制在满足阈值的计算节点间连接。$\theta_S$ 与 $\theta_T$ 分别控制准入空间和分块范围，即使默认数值相同，也属于不同决策参数。

当部署中不存在合格连接、传输载荷不超过块长，或块间没有新的资源竞争时，传输分块不产生实质性的调度重排。块间是否有可发送的 Decode 还受 GPU 执行进度和网卡可用性限制。因此，传输分块的作用依赖长消息、共享通信资源与就绪 Decode 在时间上的重叠。

## 5 理论性质与机制分析

### 5.1 执行合法性与准入可达性

**命题 1：层兼容执行图的无环性与完整覆盖。** 对满足式（1）的部署，按照式（2）构造执行图。若入口仅连接起始层为零的节点，输出端仅接收已完成边界为 $L$ 的请求，则任意入口至输出端完整路径均无 GPU 环，并在每跳仅执行未完成后缀的语义下，连续且不重复地覆盖 $[0,L)$。

**证明。** 对任意 GPU 边 $(i,j)$，式（2）给出 $b_j>b_i$。若存在 GPU 环，沿环将得到严格递增的边界序列最终返回原边界，产生矛盾，故执行图无环。设一条完整路径依次经过 $i_1,\ldots,i_m$。入口条件使第一跳执行 $[0,b_{i_1})$；相邻跳的层兼容条件保证 $i_{k+1}$ 已驻留全部待执行区间 $[b_{i_k},b_{i_{k+1}})$。这些区间首尾衔接且两两不交，输出条件又要求 $b_{i_m}=L$，其并集即为 $[0,L)$。证毕。

该性质建立了部署表示、路由结果与实际层执行之间的一致性。它以层操作顺序和驻留区间为对象；运行时仍须满足实际并发对应的 KV 容量要求。

**命题 2：空间准入保留规范路径的可达性。** 若规范图至少包含一条入口至输出端完整路径，则由式（8）至式（10）生成的准入图也至少包含一条完整路径，且所有准入路径均满足层兼容关系。

**证明。** 规范连接在构造时检查为完整合法图的子集，额外边也直接从完整合法图中选取，因此

$$
\mathcal E_{\mathrm{can}}\subseteq\mathcal E_{\mathrm{adm}}
\subseteq\mathcal E_{\mathrm{full}}.
\tag{19}
$$

任一规范完整路径的边均保留于准入图，可达性成立。另一方面，准入图的每条边均属于完整合法图，故其 GPU 转换满足式（2），由命题 1 得到完整路径的层覆盖性质。证毕。

进一步有

$$
\mathcal P(\mathcal E_{\mathrm{can}})
\subseteq\mathcal P(\mathcal E_{\mathrm{adm}})
\subseteq\mathcal P(\mathcal E_{\mathrm{full}}).
\tag{20}
$$

式（20）描述可选路径空间的包含关系。路径空间收缩后，会话分布和批量执行随之改变，因此该包含关系本身不决定线上延迟或吞吐的大小关系。

### 5.2 固定快照下的路由最优性

**命题 3：可加代理代价下的最优路径。** 给定固定部署、固定准入图和一次固定资源快照，若每条转换边的代价按式（15）确定且不依赖到达该边前的路径历史，则算法 1 返回准入图中累计代理代价最小的完整路径。

**证明。** 根据命题 1，按驻留层终点递增处理节点构成合法拓扑次序。入口状态的最优代价为零。假设处理 GPU $j$ 前，其所有可达前驱状态均已得到最优累计代价。任何到达 $j$ 的可行路径均由某一前驱状态的路径和进入 $j$ 的转换组成。由于转换代价在固定快照下不随更早的路径历史变化，式（16）枚举所有合法前驱并取最小值，即得到到达 $j$ 的最优代价。按拓扑次序归纳，所有可达状态均满足该性质。最后加入各候选输出连接的代价并取最小值，得到完整路径的最小累计代理代价。证毕。

若将所有转换代价预先计算并按邻接边组织，DAG 动态规划需要 $O(|\mathcal V_x|+|\mathcal E_{\mathrm{adm}}|)$ 次状态与边处理。当前实现逐节点扫描已有状态并检查前驱的出链，还需构造资源快照与求和层服务画像，因此不能直接以该邻接表复杂度代表完整在线决策开销。

固定快照最优性针对式（15）的代理目标。真实执行过程中，后续到达、批量形成、网卡共享与分块让出均会改变资源状态。在线路由因此将该最短路径解作为新会话的决策依据，而实际首 token 延迟和 Decode 间隔由后续调度共同决定。

### 5.3 传输分块的语义与局部占用界

**命题 4：载荷守恒与完整交付。** 对一条未丢失、未重复发送且最终完成的 Prompt 分块传输，若每次续传发送 $\min\{q,\text{剩余字节数}\}$ 字节，路径及载荷内容保持不变，则总发送字节数等于原载荷 $M$，且接收端只在全部字节发送完成并经过一次原传播时延后获得该请求。

**证明。** 初始未发送字节数为 $M$。每完成一个块，累计发送量增加本块字节数，未发送量减少同一数值，二者之和始终为 $M$。终止时未发送量为零，故累计发送量为 $M$。中间块结束事件仅释放资源并安排调度与续传，不触发接收端交付；最后一个块结束后才进入原传输的传播与交付流程。因此，下游收到的逻辑载荷与原传输相同，且只在完整发送之后继续执行。证毕。

对于已获配固定正带宽 $v$ 的单个块，在该块连续序列化期间带宽不变的条件下，有

$$
t_h^{\mathrm{ser}}=\frac{M_h}{v}\leq\frac{q}{v}.
\tag{21}
$$

当原载荷 $M>q$ 时，分块将原本 $M/v$ 的一次连续序列化占用分解为多个不超过 $q/v$ 的区间。式（21）界定的是该 Prompt 传输单个块的占用时间，不包含其他传输、GPU 执行、暂停续传或传播时延。

令 $w_h$ 为第 $h$ 个块发送完毕至下一块恢复之间的等待。在固定带宽、忽略逐块额外软件开销的模型下，从首块开始发送至完整接收的时间为

$$
t_{\mathrm{recv}}-t_{\mathrm{start}}
=\frac{M}{v}+\sum_{h=1}^{H-1}w_h+\delta_{ij}.
\tag{22}
$$

式（22）说明分块没有减少 Prompt 的字节序列化工作，而是允许其他就绪传输插入其中。Prompt 可以承担额外等待，以换取其他会话更早使用资源的机会。当前仿真未完整建模每块固定的软件与协议开销，因此实际部署中的粒度选择还需要相应开销测量。

### 5.4 模块交互与作用条件

RCAPS 的几个决策共享同一执行过程。放置搜索改变复制结构时，会同时改变规范路径、合法跨副本连接以及 GPU 上的会话分布；在线路由利用实时状态选择路径时，会改变后续各节点形成批量的机会；空间准入限制路径空间时，可能减少计算分散，也可能增加规范连接上的竞争；传输分块则在竞争已经形成的连接上增加资源让出机会。因此，完整设计的效果不能由各模块相对于不同参照配置的收益简单相加。

可以用一个简化的批量工作表达式说明其中的联系。设单层 Decode 批量为 $m$ 时的执行时间为 $g^D(m)$，其单位 token 工作为 $g^D(m)/m$。当服务画像在相关批量区间具有更低的单位 token 工作时，会话在共同计算节点上形成较大批量有助于降低计算工作。然而，相同的会话集中也会提高共享连接上的到达强度。计算聚合收益与网络等待变化分别决定了最终响应性的不同部分。

空间准入与传输分块针对这一联系作用于不同位置。空间准入限制会话可以选择的路径范围，从空间上改变资源共享；传输分块保持会话路径不变，通过块边界改变传输的连续占用。当路径分散确实削弱 Decode 聚合，且长 Prompt 正在阻塞就绪 Decode 时，两种控制具有同时发挥作用的条件。若缺少可替代路径，空间准入可调节的空间有限；若不存在合格长传输或块间没有竞争请求，传输分块不产生相同的调度作用。这些条件解释了为何工作量变化与尾部延迟变化可能不一致。

为刻画两种控制的交互，固定部署、在线路由、负载轨迹和其他执行条件，记 $Y_{st}$ 为是否启用空间准入与传输分块的四种条件下的同一正值性能指标，$s,t\in\{0,1\}$。可采用对数交互量

$$
\mathcal I_Y=
\log Y_{11}-\log Y_{10}-\log Y_{01}+\log Y_{00}
=\log\frac{Y_{11}Y_{00}}{Y_{10}Y_{01}}.
\tag{23}
$$

对于越小越好的指标，$\mathcal I_Y<0$ 表示在该条件和该指标上，两项控制的联合变化优于乘法独立参照；符号与稳定性需要在匹配种子中分别检查。式（23）用于分析空间准入与传输分块的条件交互，放置方案与路由状态信息仍需在完整系统中单独替换检验。

上述性质分别给出层执行合法性、规范路径保留、固定快照代理最优性以及分块交付语义。完整 RCAPS 的系统价值则取决于这些机制在给定算力画像、网络与负载条件下共同形成的运行结果，需以端到端表现、完成情况和资源工作量联合评价。
