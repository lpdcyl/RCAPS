# RCAPS 写作蓝图

更新于 2026-10-27。以完整 RCAPS 为论文对象，按现有实现与已核对实验组织正文。本文件是写作入口；数据充分性和未完成项沿用 [论文证据状态](RCAPS_V4_EVIDENCE_STATUS_CN.md)，不重新定义实验协议。

## 1. 题目与中心问题

建议工作题目：**RCAPS：面向异构大模型推理的放置与路径执行控制**。

英文工作题目：**RCAPS: Placement and Path Execution Control for Heterogeneous LLM Serving**。

中心问题：**在算力和网络异构、Prompt 与 Decode 共享资源的环境中，怎样构建并使用可执行路径，改善请求响应性，同时明确计算工作量的代价？**

全文要说明的设计认识：可执行路径的数量、请求在路径间的分布和传输的连续占用共同影响服务表现。灵活选路可以缓解等待，但也可能分散 Decode 批量；聚合有利于降低工作量，却不保证最短响应时间。因此需要分别控制放置提供的路径结构、会话使用路径的方式，以及长传输让出资源的时机。

这是一篇完整系统设计与机制分析论文。外部比较检验整体价值，模块对照解释设计选择，负结果界定适用条件。当前实现是分层启发式决策，不把它写成一个已求解的全局联合最优化问题或自动寻优的反馈控制器。

## 2. 三项工作在同一条主线中的位置

| 工作 | 要解决的具体问题 | 方法内容 | 正文要让读者记住的内容 |
|---|---|---|---|
| 工作一：异构放置与可执行路径构建 | 模型怎样部署，部署后有哪些合法执行选择？ | M1 表示层兼容关系与可达性；M2 在资源限制下搜索层段与副本结构 | 放置既决定容量与复制结构，也决定后续路由能选择什么 |
| 工作二：实时资源感知的会话选路 | 有了候选路径，当前请求该走哪一条？ | M3 结合服务画像、实时等待与活跃会话代价选择完整路径，后续 Decode 绑定该会话路径 | 路由考虑当前资源竞争，响应性收益可能伴随更高 GPU 工作 |
| 工作三：面向 Decode 的时空执行整形 | 选择空间过度开放、长 Prompt 传输持续占用时，如何约束执行？ | S 保留规范结构并选择性开放绕行边；T 对合格慢链路上的 Prompt 激活传输分块让出 | S 主要影响会话分散和批量效率，T 主要影响传输阻塞；两者作用依赖环境 |

结构图按实际调用关系画：**M1/M2 构建部署与合法图 → S 生成准入图 → M3 选择会话路径 → 执行器执行，T 在传输过程中让出资源**。工作三跨越选路前和传输时两个位置，不画成 M3 后面一个独立的串行阶段。

M1 作为合法性基础进入工作一，用性质说明和结构检查支撑。M2 是有界搜索；M3 不是逐 token 重路由；S 是静态路径/边准入而非拒绝请求；T 是固定粒度传输分块而非计算分块或自适应块长。论文名称应与这些实际能力一致。

## 3. 引言怎样展开

引言围绕下面五段写，每段推进一个问题。

1. **任务与困难。** 从异构资源上提供大模型推理服务切入，明确目标是请求响应性和有效完成情况。介绍 Prompt 与 Decode 的不同执行需求，以及层放置、GPU 计算和跨节点传输的共同约束。背景论断在正式稿中补入已经核实的相关文献。
2. **具体张力。** 解释可用路径更多、负载更分散、批次更大这几个局部目标为什么不能互相替代。用本系统的一组动机观察说明：避免排队的路由可能提高计算工作量，而强化聚合也可能使请求等待更久。将这些陈述限定为观察与待检验机制，不替整个领域假定统一缺陷。
3. **核心思路。** 提出分别控制路径构建、路径使用和传输占用。说明放置与路由之间还需要确定开放哪些合法边，执行阶段还需要为就绪 Decode 提供传输机会。
4. **方法概览。** 用一个自然段介绍完整 RCAPS，再用三句话解释三项工作。V3/V4 留在实现和复现说明，不用于串联论文论证。
5. **结果与贡献。** 先陈述共同设置下完整系统相对外部适配器的结果，再说明消融揭示的工作量代价和环境依赖。贡献以实际设计和被测能力表述；最近工作差异需要单独用文献和配置对齐论证。

可以作为引言核心段的草稿：

> 我们研究异构资源上的大模型推理服务，其中层放置决定可执行路径，在线路由决定会话在这些路径上的分布，传输调度决定资源何时可以被后续请求使用。这些决策影响不同的性能因素：绕开繁忙资源有助于缩短等待，集中会话有助于形成更大的 Decode 批量，而长 Prompt 传输可能延迟已就绪的 Decode 通信。RCAPS 分别控制部署结构、路径开放范围、会话选路与传输让出时机，并通过完整系统比较及受控替换，评价这些控制对响应时间、完成情况和 GPU 工作量的影响。

## 4. 贡献怎样写

下面三条是技术贡献的工作表述，不预先使用“首次”“最优”或未经查新支持的创新强度：

- 构建面向异构资源的层兼容执行表示与放置流程，将层段、副本和物理连接转化为可供在线调度使用的合法路径空间。
- 设计实时资源感知的会话选路方法，在既定部署和准入空间内结合服务、等待及活跃会话代价，控制新请求的执行路径。
- 设计作用于路径开放范围和 Prompt 传输占用的时空执行整形，并用完整系统消融、环境变化与固定工作量实验说明其条件收益、交互和计算代价。

三项贡献共同服务于一个系统问题，不要求每一项在所有条件下同时改善全部指标。实验中的模块替换说明设计选择的价值与代价；技术新颖性仍需对最近工作逐项说明，不能由正向数值或贡献段措辞代替。

## 6. 实验按问题组织

| 顺序 | 论证问题 | 采用的证据 | 正文结论 |

| 3 | S 和 T 分别改变什么？ | 完整系统的 S/T 替换；完整 2×2；路径数、Decode batch、等待与工作量 | S 的聚合/工作量作用与 T 的传输等待作用分别解释，交互单独讨论 |
| 4 | 这些解释能否经受环境变化？ | singleton1、慢链路减半、Prompt 占比变化；既有块长/范围、拓扑结果 | 展示哪些因素改变收益，明确固定默认配置的局限 |

M1 的结构性质与六种实际布局检查放在系统模型/正确性部分，详细负例放附录。工程日志、原生崩溃、完整逐种子表和复现材料放附录或 artifact；影响比较覆盖的失败必须在正文对应表附近交代。

每组结果段按“问题 → 观察 → 解释 → 适用范围”写。解释来自路径、batch、等待等联合观测，不能把相关统计量当成已经完成的独立因果分解。

## 7. 两种比较不要混淆

**完整 RCAPS 对外部方法**检验整个设计在共同条件下的竞争力。当前两个较低共同负载点同时出现延迟和 GPU 工作优势。

**完整 RCAPS 对内部简化配置**检验保留某项决策所带来的变化。静态路由或受限放置可以使用更少 GPU 工作，却响应更慢；完整系统选择了不同的运行点。外部主结果与内部工作代价使用不同参照对象，两者可以同时成立。

因此，摘要中的“降低 GPU 工作”必须明确对谁、在哪些条件下；消融中的工作量增加也应正常报告。现有系统没有在线切换最优配置的机制，不能把这些取舍写成已经实现自动最优权衡或已证明 Pareto 最优。

## 8. 摘要工作稿

> 异构大模型推理服务需要同时处理层放置、在线资源竞争与 Prompt/Decode 的执行差异。请求可以利用多条路径避开繁忙资源，但路径分散也会影响 Decode 批量效率，长 Prompt 传输则可能延迟已就绪的 Decode 通信。我们提出 RCAPS，通过层兼容表示与有界放置搜索构建可执行路径，结合实时资源状态选择会话路径，并采用保留规范结构的路径准入和慢链路 Prompt 传输分块控制执行。在基于 LLaMA-70B 画像的两个异构拓扑仿真中，在各拓扑一个共同较低负载点、三个种子的配对比较下，RCAPS 相对 Helix、Swarm 和 Separate Pipelines 的请求级 TPOT P95 降低 62.95%–79.59%。完整系统消融与固定工作量实验表明，放置与路由的响应性收益可伴随更高计算工作；路径准入的工作量收益与其延迟收益也不总是一致。结果说明了联合考虑路径结构、会话分布与传输占用的设计价值，以及该设计随执行画像和负载变化的适用边界。

摘要中的数值来源：[最终验证报告](../experiments/v4_validation/RESULTS_CN.md)外部比较部分。相对量为逐种子比值变化的均值；请求级 TPOT P95 是每请求已观察到的平均 Decode 间隔的 P95。正式摘要可在统一术语后缩短该定义，评估部分必须保留。此稿未加入未经核实的文献差异或完整最近系统优越性结论。

## 9. 实际写作顺序

先写方法章和实验章：把实际决策及每个结果对应的问题写清。然后写引言，将其中的研究动机、核心认识和贡献与正文逐项对应。最后压缩摘要、确定标题。相关工作和真实硬件证据的未完成项单独推进，不通过扩大写作措辞填补。

当前可以据此形成连贯正文。是否达到目标会议的贡献强度，仍取决于完整方案相对最近工作的实质区别，以及与部署主张相匹配的验证；本蓝图不把这两项判定为已解决。
