## 1. 题目与中心问题

建议工作题目：**RCAPS：面向异构大模型推理的放置与路径执行控制**。

英文工作题目：**RCAPS: Placement and Path Execution Control for Heterogeneous LLM Serving**。

中心问题：**在异构 GPU 与非均匀网络构成的流水线推理系统中，如何通过模型部署与会话调度，协调网络分流、Decode 批处理和会话持续服务负担，改善吞吐与尾延迟？**

全文要说明的设计认识：可执行路径的数量、请求在路径间的分布和传输的连续占用共同影响服务表现。灵活选路可以缓解等待，但也可能分散 Decode 批量；聚合有利于降低工作量，却不保证最短响应时间。因此需要分别控制放置提供的路径结构、会话使用路径的方式，以及长传输让出资源的时机。

这是一篇完整系统设计与机制分析论文。外部比较检验整体价值，模块对照解释设计选择，负结果界定适用条件。当前实现是分层启发式决策，不把它写成一个已求解的全局联合最优化问题或自动寻优的反馈控制器。

## 2. 三项工作在同一条主线中的位置

| 工作 | 要解决的具体问题 | 方法内容 | 正文要让读者记住的内容 |
|---|---|---|---|
| 工作一：异构放置与可执行路径构建 | 模型怎样部署，部署后有哪些合法执行选择？ | M1 表示层兼容关系与可达性；M2 在资源限制下搜索层段与副本结构 | 放置既决定容量与复制结构，也决定后续路由能选择什么 |
| 工作二：队列与会话感知的在线路由 | 有了候选路径，当前请求该走哪一条？ | M3 结合服务画像、实时等待与活跃会话代价选择完整路径，后续 Decode 绑定该会话路径 | 路由考虑当前资源竞争，响应性收益可能伴随更高 GPU 工作 |
| 工作三：面向 Decode 的时空执行整形 | 选择空间过度开放、长 Prompt 传输持续占用时，如何约束执行？ | S 保留规范结构并选择性开放绕行边；T 对合格慢链路上的 Prompt 激活传输分块让出 | S 主要影响会话分散和批量效率，T 主要影响传输阻塞；两者作用依赖环境 |

结构图按实际调用关系画：**M1/M2 构建部署与合法图 → S 生成准入图 → M3 选择会话路径 → 执行器执行，T 在传输过程中让出资源**。工作三跨越选路前和传输时两个位置，不画成 M3 后面一个独立的串行阶段。

M1 作为合法性基础进入工作一，用性质说明和结构检查支撑。M2 是有界搜索；M3 不是逐 token 重路由；S 是静态路径/边准入而非拒绝请求；T 是固定粒度传输分块而非计算分块或自适应块长。论文名称应与这些实际能力一致。

### 2.1 沿用导师汇报的双重动机

本节依据用户提供、标题为“2026-10-14 实验进展汇报”的 Word 文档及其中“两个动机实验”“工作一”“工作二”“工作点三”。原文件名为 `202601014-异构GPU推理模型放置调度实验汇报.docx`。本蓝图只记录主线对应关系，原始汇报未修改，其中的未来工作列表不自动转化为新实验任务。

原汇报已给出较具体的矛盾：长 Prompt 在慢链路上的占用会阻塞就绪 Decode，增加路径有助于网络分流；但过度分流会削弱 Decode 批处理局部性，增大计算工作。活跃会话后续还会持续产生 Decode，当前队列长度不能完整描述这部分服务负担。因此，论文仍围绕异构推理的吞吐与尾延迟展开，GPU 工作量用于解释机制与代价，不另立一篇以工作量最小化为目标的论文。

三项工作的承接关系是：部署提供具有分流能力的合法结构；队列与会话感知路由决定新会话如何使用结构；时空执行整形约束路径分散并在长传输中提供让出机会。当前传输分块可视为对原汇报网络侧动机的直接补充，与已有路径空间控制共同构成第三项工作。原报告提出“根据瓶颈条件调整”是当时的后续设想，当前实现仍为静态准入和固定块长，不能写成已经完成自适应闭环。

旧汇报的放置交叉、会话项消融和短窗口机制探针应保留配置与时间身份。动机中的物理现象可以沿用，经核对后使用历史实验说明其来源；完整 RCAPS 的主表和最终组件结论使用当前对应配置的证据，不把旧结果直接改名为最终方法结果。


## 3. 引言怎样展开

引言围绕下面五段写，每段推进一个问题。

1. **任务与困难。** 从异构资源上提供大模型推理服务切入，明确目标是请求响应性和有效完成情况。介绍 Prompt 与 Decode 的不同执行需求，以及层放置、GPU 计算和跨节点传输的共同约束。背景论断在正式稿中补入已经核实的相关文献。
2. **具体张力。** 解释可用路径更多、负载更分散、批次更大这几个局部目标为什么不能互相替代。用本系统的一组动机观察说明：避免排队的路由可能提高计算工作量，而强化聚合也可能使请求等待更久。将这些陈述限定为观察与待检验机制，不替整个领域假定统一缺陷。
3. **核心思路。** 提出分别控制路径构建、路径使用和传输占用。说明放置与路由之间还需要确定开放哪些合法边，执行阶段还需要为就绪 Decode 提供传输机会。
4. **方法概览。** 用一个自然段介绍完整 RCAPS，再用三句话解释三项工作。V3/V4 留在实现和复现说明，不用于串联论文论证。
5. **结果与贡献。** 先陈述共同设置下完整系统相对外部适配器的结果，再说明消融揭示的工作量代价和环境依赖。贡献以实际设计和被测能力表述；最近工作差异需要单独用文献和配置对齐论证。

可以作为引言核心段的草稿：

> 我们研究异构资源上的大模型推理服务，其中层放置决定可执行路径，在线路由决定会话在这些路径上的分布，传输调度决定资源何时可以被后续请求使用。这些决策影响不同的性能因素：绕开繁忙资源有助于缩短等待，集中会话有助于形成更大的 Decode 批量，而长 Prompt 传输可能延迟已就绪的 Decode 通信。RCAPS 分别控制部署结构、路径开放范围、会话选路与传输让出时机，并通过完整系统比较及受控替换，评价这些控制对响应时间、完成情况和 GPU 工作量的影响。

## 4. 贡献怎样写

下面三条是技术贡献的工作表述，不预先使用“首次”“最优”或未经查新支持的创新强度：

- 构建面向异构资源的层兼容执行表示与放置流程，将层段、副本和物理连接转化为可供在线调度使用的合法路径空间。
- 设计实时资源感知的会话选路方法，在既定部署和准入空间内结合服务、等待及活跃会话代价，控制新请求的执行路径。
- 设计作用于路径开放范围和 Prompt 传输占用的时空执行整形，并用完整系统消融、环境变化与固定工作量实验说明其条件收益、交互和计算代价。

三项贡献共同服务于一个系统问题，不要求每一项在所有条件下同时改善全部指标。实验中的模块替换说明设计选择的价值与代价；技术新颖性仍需对最近工作逐项说明，不能由正向数值或贡献段措辞代替。

## 7. 两种比较不要混淆

**完整 RCAPS 对外部方法**检验整个设计在共同条件下的竞争力。当前两个较低共同负载点同时出现延迟和 GPU 工作优势。

**完整 RCAPS 对内部简化配置**检验保留某项决策所带来的变化。静态路由或受限放置可以使用更少 GPU 工作，却响应更慢；完整系统选择了不同的运行点。外部主结果与内部工作代价使用不同参照对象，两者可以同时成立。

因此，摘要中的“降低 GPU 工作”必须明确对谁、在哪些条件下；消融中的工作量增加也应正常报告。现有系统没有在线切换最优配置的机制，不能把这些取舍写成已经实现自动最优权衡或已证明 Pareto 最优。

## 8. 摘要工作稿

> 异构大模型推理服务需要同时处理层放置、在线资源竞争与 Prompt/Decode 的执行差异。请求可以利用多条路径避开繁忙资源，但路径分散也会影响 Decode 批量效率，长 Prompt 传输则可能延迟已就绪的 Decode 通信。我们提出 RCAPS，通过层兼容表示与有界放置搜索构建可执行路径，结合实时资源状态选择会话路径，并采用保留规范结构的路径准入和慢链路 Prompt 传输分块控制执行。在基于 LLaMA-70B 画像的两个异构拓扑仿真中，在各拓扑一个共同较低负载点、三个种子的配对比较下，RCAPS 相对 Helix、Swarm 和 Separate Pipelines 的请求级 TPOT P95 降低 62.95%–79.59%。完整系统消融与固定工作量实验表明，放置与路由的响应性收益可伴随更高计算工作；路径准入的工作量收益与其延迟收益也不总是一致。结果说明了联合考虑路径结构、会话分布与传输占用的设计价值，以及该设计随执行画像和负载变化的适用边界。

摘要中的数值来源：[最终验证报告](../experiments/v4_validation/RESULTS_CN.md)外部比较部分。相对量为逐种子比值变化的均值；请求级 TPOT P95 是每请求已观察到的平均 Decode 间隔的 P95。正式摘要可在统一术语后缩短该定义，评估部分必须保留。此稿未加入未经核实的文献差异或完整最近系统优越性结论。

### 11.1 中心主张与三项工作的关系

建议将中心主张固定为：**RCAPS 通过分段放置、队列与会话感知路由以及时空执行整形，协调网络分流、Decode 批处理与会话持续服务负担，在已测异构环境中改善推理服务表现，并解释对应的资源代价与适用边界。**

据此，分段放置提供可执行结构，实时选路利用这些结构改善响应，时空执行整形分别调节路径分散与长消息阻塞。空间准入的主要证据指向批量形成及工作量，传输分块的主要证据指向有竞争时的 Decode 等待与延迟。三者共同构成完整 RCAPS，不将新增的时空机制替代为全文唯一贡献。

主张限定在当前画像驱动仿真与已测条件。正文不承诺每个组件同时降低延迟和计算工作，不主张所有外部系统在整个负载范围内都被支配，不将可加代理路径最优性扩展为端到端最优性。保留“选择了怎样的响应性—工作量取舍”，不改写成系统已经自动找到最优取舍。

### 11.3 已完成补证一：最终系统中的会话持续服务代价

**实验问题与结果。** 导师汇报将“队列之外的 KV 会话持续负担”作为在线路由的重要内容。最终系统只关闭活跃会话计数项的对照已在单集群700和三集群320各运行三个种子。相对no_session，完整RCAPS的TPOT P95均值分别低20.40%和26.30%；三集群TTFT低4.40%，单集群TTFT变化+0.05%；GPU工作/token分别高48.94%和76.84%。两组请求轨迹、目标输出完全配对，全部请求均完成。结果明确表现为延迟—工作量取舍，而非各项指标同时改善。

`rcaps/v4/admission.py` 的 `no_session` 控制将活跃会话计数置零，同时保留实时GPU/链路快照；与静态状态控制不同，它不同时清空等待状态。本批使用这一隔离控制，结果与冻结报告配对。

**对照解释。** 消融只移除路径代价中的活跃会话项，保留放置、准入边、实时GPU/链路等待、单token服务画像、传输分块、Decode优先与同跳合并、KV路径绑定。这里考察的是活跃会话引入的持续Decode服务负担，不是移除KV缓存，也不是比较是否预留真实KV剩余容量。关闭该代价后路径从单集群约12条减至约10条、三集群从8条减至4条；三集群最大单路径承载约79%请求，Decode批量扩大并伴随较低GPU工作。该机制证据与路由分散解释一致，但不构成独立中介因果证明。贡献应写为“按会话持续服务负担计价，以分散路径改善响应性，同时承担额外GPU工作”，并报告其负担和适用范围。

**执行状态。** 6个正式no_session窗口均完成，使用1800秒到达前缀、5400秒观察上限及种子0/1/2；与6个冻结完整RCAPS结果逐种子配对并验证输出守恒。本轮共复用9个参照，其中另外3个无分块结果用于成本对照。结果文件见核心补证报告及逐种子JSON/CSV。

**结果解释。** 所有会话条件均完成同一工作量。完整系统有较低TPOT、相近单集群TTFT和较低的三集群TTFT，同时承担更多GPU工作。实际路径数与批量变化提示会话计价缓解路径集中；此机制证据属于伴随变化，不能写成独立中介因果分解。正文不应用历史版本差异替代本批最终系统结果。

历史实现对照仅作为研究背景：[状态项实验报告](../experiments/v3_method_validation/m3_formal_report.md)，其中记录了不同实现身份与复跑稳定性限制。最终系统的正式证据以[本轮核心补证报告](../experiments/v4_core_validation/RESULTS_CN.md)及逐种子结果为准。

### 11.4 已完成补证二：传输分块的净收益与开销边界

**剩余缺口与当前补证。** 网络减半、Prompt占比、块长和作用范围实验已覆盖条件作用；本轮另外完成每个中间块边界1/10/100ms额外资源持有的仿真敏感性。该资源占用是在载荷发送后、资源释放前加入，不增加字节。它不能校准真实逐块协议、软件处理和恢复开销；原始调度墙钟时间也不是实际通信测量。

**已运行结果与缺失。** 三集群320下，1ms、10ms成本组均有三个完整种子；相对无分块，TPOT P95均值分别低14.51%和13.93%，GPU工作/token分别高5.41%和4.36%。相对零附加成本完整分块，TPOT变化仅−0.21%和+0.47%，未显示稳定的额外改善或明显均值损失。100ms成本seed1发生原生访问冲突，另外两个种子的TPOT相对零成本条件分别高5.07%和6.19%，TTFT分别高8.41%和10.48%；该组三种子不完整，不能估计总体均值或阈值。失败源日志位于 `experiments/v4_core_validation/execution/runs/boundary_cost/multi/load320/hold_100ms/seed1/worker.log`。

本轮成本占用的是原链路、发送NIC和接收NIC额度，取值在预先固定后运行。它给出三个离散仿真点，不是连续曲线；由于100ms组失败，也不能声称收益交叉或可靠阈值。假设性开销必须标注为假设，不包装成实测校准。

**证据范围。** 已报告TPOT、TTFT、吞吐、工作量、完成率、积压和网络等待。成本假设结果不能替代真实硬件/协议微基准；真实端到端系统收益仍需真实引擎验证。负结果和缺失窗口保留，不通过改变默认块长挽回本轮结果。

### 11.5 主线必须重排的证据：无需新增模拟窗口

用现有 21 个全部完成的尾部窗口整理两个场景的“响应性—计算工作”对照：分别报告完整 RCAPS、静态状态路由、受限放置，以及三集群中的空间/时间替换。相同场景内按工作负载种子配对，给出 TPOT、TTFT、总 GPU 忙碌时间、GPU 工作/token 和完成时刻。不同到达队列或观察分母不能直接混为同一组。

该整理回答“收益付出了什么、时空整形缓解了哪一部分代价”。它是现有配置运行点的比较，不是通过密集调参获得的全局 Pareto 前沿。也无需为比较响应性而强制所有调度器消耗完全相同的 GPU 忙碌时间，因为该量本身就是待解释的结果。

机制解释优先使用同一批固定工作量记录中的路径、Decode batch、分阶段 GPU 工作及已结算等待，配合窗口边界的未结算量。注意完整队列统计不自动构成严格因果分解；若缺少某一归因量，只陈述共同变化，不以新运行重复已经回答的工作守恒问题。

### 11.6 外部比较与真实系统证据的处理

**高负载失败继续留档，当前不重启该队列。** 新增 Swarm/SP 高负载 12 个窗口中只有 1 个成功，没有完整三种子比较组。按用户当前决定，不把修复这些窗口设为其他工作的前置条件。正文将全外部方法比较限制在已有两个共同负载点，并单独呈现 Helix 的更广负载覆盖。这样仍可写完整系统的条件优势，但不能写跨负载优于所有外部方法或最大可持续容量提高。

若之后保留跨负载优势主张，则共同运行区间内的额外外部比较恢复为必要项。新增共同负载需按负载协议而非 RCAPS 的胜负选择，各方法使用同一轨迹与报告口径；它不能覆盖或取代原高负载失败。当前不提出另一条大范围扫描。

**邻近机制证据不扩大身份。** 已有 Parallax-inspired 对照比较会话选路目标，可放在路由机制部分。它既不是完整 Parallax 系统对比，也没有回答时空整形相对最近传输调度方法的差别。若正文要主张超越某个最近系统，应先核实其相关能力与比较接口，再补忠实对照；不靠额外改名或一个内部随机控制解决新颖性问题。

**真实系统证据仍是独立缺口。** 现有公开结论应落在画像驱动仿真范围。若以实际异构推理服务的实现与性能作为投稿主张，仍需真实画像、通信开销和端到端原型证据。前述两组补证只能加强当前机制论证，不构成 CCF-A 录用充分性或完整方法新颖性的判定。

### 11.7 本轮停止扩展的项目

- 不增加完整组件的全组合枚举，不要求所有组件在每个环境都降低全部指标。
- 不重复已完成的固定工作量、网络减半、Prompt 占比和 singleton 画像反事实。
- 不继续扩展块长、拓扑、模型或负载数量，除非新的结果使主线解释发生具体歧义。
- 不为了“纯边界收益”追加等复制容量放置实验，除非正文坚持这项更窄的主张；当前按完整放置策略比较并报告容量差异。
- 不增加逐 token 重路由、KV 迁移、自适应准入或自适应块长等新算法。
- 不把三种子自动写成统计显著，不用失败窗口换算零吞吐或无穷延迟。

**结果组织顺序：**先呈现完整 RCAPS 相对 Helix/Swarm/SP 的共同负载主结果，再报告从完整系统出发的放置、实时路由、空间准入与传输分块消融；将会话代价结果明确写成延迟—GPU 工作取舍，将分块敏感性明确限定为假设成本点，随后分析路径分散、Decode 批量、网络等待及环境条件。S×T 四格不能替代放置、路由或会话项独立消融，组件变化的结果也不能相加为总收益。同规模准入选边只支撑更窄的条件主张。外部方法比较范围及实际系统校准缺口保持明确。

### 11.8 条件补证：特定准入规则是否超出一般路径收缩

**待区分的解释。** 现有规范、稀疏、完整路径空间比较同时改变边的数量和位置，支持“限制路径空间具有条件价值”，尚不能说明“围绕慢规范边选择高速额外连接”优于其他同规模合法选择。如果将这条规则本身作为技术贡献，应补这一机制对照；若不做，则将其写成当前实现采用的启发式，不赋予规则优越性的结论。

**最小对照。** 从完整 RCAPS 出发，固定放置、实时路由、传输分块、画像和到达轨迹，只替换额外边选择。所有条件保留同一规范边集，并添加同样数量的非规范边。优先从同一高速合法候选池选边，以避免仅用大量慢边构造过弱对照；在不查看服务性能的前提下，预登记三种不同的随机合法子图及其生成种子。规范边保留完整路径，仍需独立检查生成图的结构及与当前准入图的差异。

当前三集群部署的已保存结果显示：完整图 58 条边，规范图 26 条边，RCAPS 准入图 30 条边。因此同规模对照保留 26 条规范边，并加入 4 条额外边。高速候选池是否足以产生不同的有效子图，应在结构检查中确定；若候选池或路径空间退化，不运行没有区分能力的对照，也不为制造差异而事后更换规则。

**建议规模。** 先用三集群 320 这一已有机制锚点，三个工作负载种子与三个预登记子图交叉，共 9 个新窗口。子图种子与工作负载种子分别记录，不把九个组合当成九个独立工作负载种子。完整 RCAPS 的三种子记录只有在全部公共配置、轨迹和测量口径匹配时才可复用。若新增指标需要改变测量代码，相关参照也应按同一新协议获取，不能直接混接。

**指标与结束条件。** 端到端报告 TPOT、TTFT、吞吐、完成率、积压和 GPU 工作/token，机制侧报告合法完整路径数、实际使用路径数、Decode batch 与传输等待。等边数不等于等可达路径数，因此将后者作为解释量，不能宣称所有结构因素都已隔离。结果若无法区分当前规则和简单稀疏化，则保留“路径空间控制”贡献，降低该特定选边规则的强调程度，不追加搜索直到得到优势。

这一对照属于完整系统中的内部机制替换，不能补作任何外部系统的完整复现，也不替代 RCAPS 对外部基线的主结果。

### 11.9 原汇报中的放置与扩展实验如何衔接

旧汇报的“Helix 放置 + 相同路由”对比，回答的是所提出放置相对外部放置的效果；最终系统当前的受限放置对照回答的是受限搜索空间相对完整放置策略的条件作用。两者问题不同，不互相改名替代。若正文保留独立的“所提出放置优于外部放置”主张，需要在共同最终执行条件下对齐比较，并事先定义外部布局的规范图接口。旧交叉实验的失败仍保留，不能为制造完整矩阵而静默修改配置。若暂不追加这项更强对照，则以完整系统外部比较、最终受限放置对照和有身份说明的历史结果分别支撑相应层次。

原汇报中的 42 节点扩展、进一步改进准入策略属于后续方向。当前收紧主线时，不把它们列为无条件必做：更多节点不自动回答会话项是否必要，新的自适应准入也会改变方法身份。先完成与当前三项工作直接对应的证据，再判断是否需要扩展规模。
