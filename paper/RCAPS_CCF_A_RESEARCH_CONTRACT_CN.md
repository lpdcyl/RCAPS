## 1. 决策：先确定可检验的论文核心，再完成必要实验

**应该先确定论文要回答的问题和允许提出的主张，再决定必做实验；不是先写定胜利结论，再补能支持它的实验。** 正确顺序是：

1. 固定研究对象、核心问题、机制解释和主张范围。
2. 将现有代码、原始结果和最近工作映射到每项主张。
3. 注册仍有决定作用的实验及其反面解释，保持已经冻结的结果可追溯。
4. 完成这些实验，包括负结果、失败与适用范围；必要时缩小或修改主张。
5. 最后定稿摘要、贡献强度、主结果与结论。

目前的总体判断是 **revise：保留完整 RCAPS 的方向，重写中心论证，并补齐决定性证据**。最近工作差异仍有 `needs-literature-search` 待决事项。这不是“思路不成立”，也不是“已具备 CCF-A 录用条件”。

必须区分三件事：已有登记批次完成；相应主张获得支持；达到某个具体会议的投稿标准。120 个成功窗口证明第一项，不自动证明后两项。

### 1.1 关于“方向 A / 方向 B”的决策

**采用方向 A 作为论文的外层主线，但保留方向 B 作为最突出的技术张力和机制解释。** 也就是说，论文对象是完整的异构 LLM 推理放置与调度系统 RCAPS；空间/时间干扰控制是 RCAPS 中最能形成统一解释的关键设计，而不是把 S/T 单独升级为全文方法。

方向 A 更符合当前代码和证据结构：外部主结果是完整 V4，M2/M3/S/T 的消融也都从完整系统出发。若改成方向 B，外部系统比较会被降为背景，论文容易退化成“固定分块和路径收缩有效”；这会直接放大与 MoLink 等工作的重叠，也无法自然解释 M1/M2/M3 的必要性。

但“异构 LLM 推理的完整放置与调度系统”本身太宽，也不是充分的新颖性主张。正文和标题不能只写“完整系统设计”，而应固定为以下更具体的问题：

> 在异构 GPU 与不均匀网络上，如何把放置所提供的潜在并行性转化为有效在线服务能力，同时控制路径分散、Decode 聚合和长 Prompt 传输之间的相互干扰？

对应的主张是：**RCAPS 通过合法执行结构、异构放置、状态感知选路以及拓扑约束的路径准入和 Prompt 传输让出，形成一个有边界的放置—路由—执行控制系统；它在明确的资源和负载条件下改善服务指标，但代价和失效条件由模块消融与机制实验共同给出。**

因此两种方向不是二选一的两个版本，而是层级关系：

| 层级 | 论文表述 | 作用 |
|---|---|---|
| 外层贡献 | **面向异构 LLM 推理的完整放置—路由—执行控制系统 RCAPS** | 组织 M1/M2/M3/S/T 和外部系统比较 |
| 核心技术张力 | **潜在并行性与有效服务能力之间的转换** | 说明为什么更多路径不一定更好 |
| 机制镜头 | **空间路径准入与时间传输让出共同控制路径分散、Decode 聚合和传输阻塞** | 解释工作三、S×T 四格和条件失效 |

方向切换不会增加或删除一套实验；它改变实验的主次和结论措辞。E1 外部比较、E3 完整系统消融仍是主证据，S/T 四格退回机制证据。若后续关键实验显示 M1/M2/M3 的整体收益不成立，才需要重新收缩到更窄的方向 B 或修改方法本身。

## 2. 建议固定的论文主线

### 2.1 研究对象、问题和核心洞察

研究对象：异构 GPU、有限显存与不均匀网络上的流水并行 LLM 服务。当前实现采用会话级路径选择，Prompt 选路后 Decode 固定该路径；不主张逐 token 重路由、在线 KV 迁移或节点故障恢复。

**核心问题：异构放置提供的候选并行能力，如何在在线请求与 Prefill/Decode 竞争下转化为有效服务能力，而不因路径分散、批量变小和长传输阻塞抵消收益？**

建议的核心洞察是一个待检验的系统设计原则：

> 放置决定可用的执行结构，实时路由决定负载落点，但更大的路由空间并不必然形成更好的服务。路由自由度同时影响绕行机会与 Decode 聚合；长 Prompt 传输的连续占用又影响 Decode 能否及时推进。因此需要把放置、实时选路与执行约束连成一个有边界的设计，而不能仅分别最大化路径选择或局部利用率。

“共同设计”在这里指接口和机制上的配合，**不等于代码实现了统一全局目标、联合最优求解或反馈控制器**。M2 是静态有界搜索，M3 是可加资源代价选路，S 是静态拓扑规则，T 是固定字节块长让出。

### 2.2 从问题到方法的因果论证

| 论证环节 | RCAPS 应写的内容 | 需要避免的替换 |
|---|---|---|
| 起点 | 异构计算与网络使完整副本和固定流水线难以同时匹配资源、延迟和负载 | 以“我们把 V3 升级为 V4”开篇 |
| 已知进展 | 已有系统研究异构放置、图选路、阶段间传输竞争 | 把这些通用技术都说成首次提出 |
| 研究张力 | 路径绕行、Decode 聚合和传输可让出性存在相互制约 | 假定路径越多越好，或所有模块收益相加 |
| 关键问题 | 如何让部署结构与在线执行共同改善服务，代价在哪里 | 只问新增 S/T 比旧实现快多少 |
| 方法 | 合法结构与异构放置 → 准入后的实时路由 → 传输执行让出 | 将 S/T 误画为 M3 后的两个独立串行阶段 |
| 证据 | 外部比较 → 完整系统替换 → 条件机制与稳健性 → 开销与边界 | 用 S×T 四格代替全部系统证据 |
| 有界结论 | 在明确硬件、画像、负载与实现范围内检验收益和代价 | 普适更快、更省 GPU、更节能、全局最优 |

尚未证明的领域缺口应写成研究问题：**本文是否能给出不同于已有部署、路由和传输调度工作的统一机制解释及有效设计？** 不能仅凭现有三个近邻文献就断言“此前没人考虑过”。

### 2.3 三个工作点如何进入全文

| 工作点 | 在统一方法中的角色 | 能主张到哪里 |
|---|---|---|
| 工作一：M1/M2 | 表达合法执行空间，在显存和拓扑限制下构造共享/复制放置 | 给出结构、算法和边界；M1 是合法性基础，不能独立包装成性能提升模块 |
| 工作二：M3 | 在既定放置与准入图中，利用实时等待、活跃会话及服务代价选择请求路径 | 检验状态信息的条件价值；已有 Decode 优先、同跳合并属于完整基础栈，不属于工作三新增 |
| 工作三：S/T | 控制开放多少合法连接，以及长 Prompt 传输连续占用多久 | 解释绕行、聚合、阻塞的折中；不宣称分块本身首创 |

**工作三推荐名称：面向 Decode 聚合与传输阻塞的时空执行整形。** 更直接的英文描述为 `Topology-constrained path admission and prompt-transfer yielding`，不必再造一个方法缩写。

可用于方法章节的准确描述：

> RCAPS 在结构化放置与状态感知路由基础上，进一步约束执行路径的开放范围及长 Prompt 激活传输的连续占用。空间部分保留规范副本连接，并按静态拓扑规则选择性开放高速跨副本边；时间部分在合格慢计算链路上按固定字节粒度分块，在块边界释放链路与 NIC 资源，为就绪 Decode 提供发送机会。本文检验这两种约束如何改变路径分散、批量执行和传输等待，以及其作用依赖的条件。

不能写成：自适应空间准入、最优 chunk、逐 token 抢占、流式下游计算，或具备正式饥饿避免/时延上界。当前代码没有相应完整机制或证明。

### 2.4 对外贡献建议按三项组织

1. **问题与设计认识：**揭示并量化异构部署中，路径自由度、批量聚合和阶段间通信竞争的制约关系。这里的“揭示”是否足够新，仍须对最近工作定点核对；不能仅靠换术语成立。
2. **完整系统设计：**给出 RCAPS 的合法执行表示、结构化放置、状态感知路由与时空执行约束，解释接口和必要条件。贡献不是模块名称的个数。
3. **证据与边界：**以外部系统比较和最终系统替换，检验何时改善延迟/完成能力、何时仅改变工作量，以及需要付出的代价。数字待必需实验结束后定稿。

论文不必把每个工程工作点各写成一条“独立首创”。保留已有有价值部件，并把真正成立的整体贡献写清楚，比强行证明三个模块分别全新更稳妥。

## 4. 概念质量评审：与实验数量分开

### 4.1 优势、风险及最小修正

可保留的优势是问题具体、方法已明确分层、机制能够被反驳。合法结构、可用路径和实际执行之间的区分，也允许解释“资源更多/路径更多但服务未必更好”。这些优点不依赖本次补实验是否成功。

| ③ 机制分析 | **可串起初步链条，还需要排查关键替代解释** | 路径、Decode batch、GPU 工作与传输等待随干预变化 | 单例 batch 的画像假设、窗口末未结算等待、单位工作量分母与会话完成差异，不能仅靠整理图表解决 |
| ④ 敏感性与泛化 | **参数敏感性已有；支撑核心机制的环境证据不足** | chunk 范围/块长、已有负载及 C2/C3 结果 | T 实际激活的网络变化、与 Prefill/Decode 竞争相关的负载变化、开销/画像校准；这些若支撑主张，就不只是加分项 |

几项不能隐藏的现有边界，数值来源均见系统总览及审计 JSON：

- M2 在单/700 相对受限放置降低 TPOT 约 31.49%，但 GPU s/token 增约 173.48%；147/112 层副本、752/376 实际候选评估。共同物理 GPU 池下允许策略改变放置容量，这本身不等于不公平，但不能解释成固定容量、相同搜索计算量下的纯边界效果。三/320 没有稳定 M2 延迟收益。
- M3 相对静态状态降低 TPOT，GPU s/token 却增加约 303.23%/256.78%；应同时报告完成率和积压，不能说每个组件都省工作量。
- 三/320：S 单独使用使 TPOT 约升 1.81%；固定 T 时 S 的 TPOT 约降 2.98%、GPU 工作约降 28.01%；固定 S 时 T 的 TPOT 约降 14.92%。这支持条件作用，不支持简单相加。
- 单集群、C2、C3 没有合格慢链路，T 不激活；C2/C3 的 GPU 工作下降不能证明 T 跨网络有效，也不能包装成稳定尾延迟改善。
- 4 MiB 与“只慢链路”是冻结选择，不是已证明的最优参数。

## 7. 必需实验与审计的最小集合

### 7.1 第一优先级：补主结果覆盖与明确竞争对象

**E1：关键负载外部比较。** 在原有单/700、三/320 条件，补 Swarm/SP 的 seed 0/1/2，共 `2 方法 × 2 场景/负载 × 3 种子 = 12` 个待注册正式窗口；其余协议沿用可比的 1800 秒、零预热、不排空主实验，复用身份与计量一致的 RCAPS/Helix 结果。共同输出 TPOT、TTFT、输出吞吐、完成率、积压、GPU s/token，并保留失败。

这 12 格只把每个基线补到共同较低/较高两点，**不等于完整负载曲线或可持续容量证据**。若正文要声称所有基线跨负载占优、提升最大可持续负载或降低稳定排队，应为所有方法补相应共同中间/近饱和点，并检查长期积压斜率与预先定义的服务目标。不能用短窗口更高输出吞吐直接推出容量提升。

**E2：最近方法的差异与可比性。** 先核实 Parallax/MoLink 的完整实现、模型与资源支持、放置和调度接口、调优范围及开销，再确定是否可在共同设定直接运行。对直接竞争者，可比完整比较是保留强外部优势主张的必要条件；无法忠实比较时，明确不适配的原因与更窄结论。不能以便利为由仅选弱旧基线，也不能先用代理代码跑出数字再称复现完成。

### 7.2 第二优先级：让现有消融可解释，而非重跑所有组合

**E3：最终系统消融口径及 M1 证据。** 优先复用已有结果，把每组替换的放置、准入规则、路由信息、执行规则、画像、到达轨迹、预算及实际开销列成控制表。M2 改放置后按同一 S 规则重建图，属于下游响应；无需强行维持同一绝对边集。

M1 的最小正确性证据是：连续层执行与严格层进度推导；导出/运行图的合法性一致性；规范图可达时 S 保留完整路径；对非法配置的拒绝检查与容量适用范围。先核对现有测试覆盖，再补缺失检查。**不关闭合法性约束做性能对比**；正 KV 容量也不能当作任意并发 KV 安全或数值推理正确性的保证。

无需机械补 `2^4` 个全组合，也不要求每个模块在每个拓扑都显著获胜。相同层副本容量或实际候选评估数下的 M2 对照，仅在主张“纯多边界效果”或“等搜索开销优势”时必需；完整策略级比较应如实报告这些差异。

### 7.3 第三优先级：排除会改变中心解释的因素

**E4：S 的画像依赖。** `simulator/event_simulator/model.py` 对单 token Decode batch 使用额外 2 倍时间修正，M3 的代价估计也有对应处理。该假设可能放大路径聚集的收益。固定已部署布局、T 条件、到达轨迹与图规则，比较完整 RCAPS 与无 S；除原画像外，至少使用一个明确登记的替代画像/单例修正条件，优先采用实测画像。各方法共享同一画像，执行器与路由预测保持一致，不能只改 RCAPS 一侧或只改服务时间。

记录路径分散、batch 分布、单例比例、每 token GPU 工作和端到端服务。去掉额外修正是诊断反事实，不宣称更真实；若收益消失，则将结论收缩为特定画像条件下的作用，不能删掉该结果。冻结历史代码不原地改写，扩展实验需有显式配置/代码版本与等价性检查。

**E5：观察窗口、完成工作量和未结算等待。** 首先从已有轨迹/输出核对未完成请求、等待统计结算点以及指标分母能否补算。若日志不足，新增一个最小固定到达前缀实验：各方法接收同一批请求、随后停止新到达，记录排空过程与总完成工作量；设置共同停止/失败规则，无法排空时保留右删失。

主要关注工作量差异较大的 full/static M3、full/restricted M2，以及 S/T 关键对照；从最有决定作用的条件开始，不重跑全部历史网格。新实验独立标注协议，不能与原不排空 1800 秒主表直接混算。用于判断工作量节省是否来自批量效率、工作组成或完成度差异，也用于发现 Prompt 长期等待。没有证据时不得直接断言原结果有幸存者偏差，也不得假设偏差不存在。

对链路等待，应记录消息累计等待、窗口末仍等待消息数量/年龄、单位 Decode token 或传输字节的归一化量。Prompt 占用重叠可用作机制关联，不能当作互斥可加的因果分摊；发送/接收 NIC 重叠不要相加。

### 7.4 第四优先级：与主线直接相关的环境变化

**E6：T 激活与失效的网络条件。** 先固定布局与工作负载，选择一组仍存在合格慢链路的不同带宽/竞争条件，以及一组 T 不激活或阻塞很弱的负对照。预登记带宽单位、S/T 阈值、慢边数量和实际 chunk 次数，不根据结果移动阈值。带宽变化同时改变 S 准入时应记录边集，并用分离 S/T 的对照解释；必要时增加固定图的诊断子实验，避免混淆。

已有单集群/C2/C3 可用于满足相容的 T 不激活负对照，但无法替代 T 激活条件下的稳健性。若要评价环境变化后整个部署流程，另行重跑 M2，作为完整系统结果，不与固定布局的因果诊断混为一组。

**E7：改变 Prefill/Decode 竞争的工作负载。** 在能够激活相应机制的拓扑，至少选择一个预登记的输入/输出长度组合变化，例如更长 Prompt 的条件；如论文另声称应对突发，则补突发到达。统一说明到达率、输入/输出长度分布和提供负载的定义。不能在相同 req/s 下增加每请求计算量后，将全部差异解释为调度鲁棒性。

E6/E7 选择最少能区分机制解释的条件；S/T 是问题核心时使用分离对照或四格，不默认每个新环境都带全部外部方法和全部参数网格。若只愿主张当前特定网络/负载下的效果，可以收缩 H4/H5 的范围，但不再称跨环境稳健。

### 7.5 与系统落地强度匹配的必要证据

**E8：开销与画像校准。** 当前已有结果是模拟器结果，不等于完整真实分布式推理部署。对本项目的系统性主张，建议作为强主张前置条件：测量 M2 搜索时间、M3 选路开销、batch 服务画像、传输分块/恢复与调度开销，并检查仿真对关键趋势和量级的拟合。仅增加 CPU 仿真窗口不能回答这些问题。

真实 GPU/NIC 上的传输与 batch 微基准可校准关键假设，但也不能代替完整系统端到端部署。如果最终论文明确声称真实部署性能，应完成与该主张相匹配的真实端到端对比；若暂无资源，诚实限定仿真/调度研究，之后按具体投稿场所判断可接受性。这是针对本论文主张的建议，不是宣称所有 CCF-A 投稿都有同一真实硬件门槛。

T 还需检查逐块软件/协议开销与 Prompt 长期等待。MoLink 的等待权重和即时块量决定是有意义的近邻机制；RCAPS 不能仅因固定分块有效就推导比其更优，或声称自己已有同样的饥饿避免性质。

## 9. 论文结构、图表和统计解释

建议正文顺序：

1. **Introduction：**问题张力、已有进展与尚需回答的问题、核心洞察、完整方法及有界贡献。
2. **Background / Motivation：**异构流水推理、请求阶段差异，用已有观察解释路径分散和传输阻塞；清楚标记它们的测量条件。
3. **RCAPS Design：**M1 合法性/系统模型，M2 放置，S 允许空间与 M3 实时路由，T 执行让出；按真实依赖写接口。
4. **Implementation / Methodology：**模拟器/实现范围、画像、基线版本与适配、控制条件、指标、开销、固定窗口协议。
5. **Evaluation：**先外部端到端，再完整系统 M2/M3/S/T，接着机制与交互，最后敏感性、泛化、开销和边界。
6. **Related Work / Limitations / Conclusion：**按投稿格式安排；相关工作要正面讨论 Helix、Parallax、MoLink，限制来自实际证据，结论只覆盖已检验范围。

最低图表骨架：完整设计图；所有可比外部方法的共同指标表/负载曲线；最终系统模块替换表；S/T 四格与路径→batch→GPU 工作、让出→等待→服务的机制图；必要的环境/开销边界图。图数不是完成条件。

统计与解释约定：

- 主结果对象是 RCAPS；V3 仅作为历史/追溯标签，执行等价确认后可叫 `RCAPS − S − T`。不能因名称相似直接重标历史结果。
- 逐种子配对、显示原始点和离散程度；三个种子不支持笼统的“统计显著”。历史三/400 Helix 缺 seed0，需明确缺失，不当齐全三种子结果。
- 现有百分比按逐种子 `RCAPS/对照−1` 后平均；绝对表是均值。不可混用比值均值和均值之比而不说明。
- 对较小更好的指标 Y，四格可记录 `I = log(Y11) − log(Y10) − log(Y01) + log(Y00)`。负值只在这个尺度/条件下表示低于无交互的乘性预期，不直接证明普适协同；两个单模块收益不能直接相加。
- 延迟与吞吐必须同时给完成率、积压；GPU 工作同时给工作组成和计量口径。平均 batch 之外应查看分布及单例比例。
- 失败、超时、不可排空及未完成样本均有去向。已看过的 seed0/1/2 是既有证据，不重新称为盲测；新增条件先冻结默认值、控制和分析规则。

## 10. 完成判据与下一阶段

下一阶段先把 E1 的 12 个窗口、E2 的竞争对象决策、E3 的控制表，以及 E4/E5 中最可能改变结论的条件写入独立扩展协议。E6/E7 按最终保留的环境主张选择最少条件；E8 按实测资源与目标论文类型明确可执行范围。不要先跑更多 chunk 点，再发现主结果与画像假设仍未解决。

开始正式写结果章节前，至少应能够回答：

- 对哪些外部方法、哪些共同资源与负载、哪些指标，RCAPS 优于或不优于对照？
- 每个最终系统替换究竟改变了什么，资源、搜索开销和完成工作量是否可解释？
- 机制结论能否排除决定性的画像与观察窗口替代解释？
- S/T 是否激活，何时互补、无效或引入代价？
- 模拟/真实实现的界线、必要开销和仍未覆盖的主张是否明确？

**达到完成判据不要求所有实验取胜。** 如果关键对照为负，保留结果并缩小主张；如果它推翻中心解释，则修改解释或方法后再独立验证。论文始终回答完整 RCAPS 的设计价值与边界，而不是回到“V4 比 V3 好多少”。
