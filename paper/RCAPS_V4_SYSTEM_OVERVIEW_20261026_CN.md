## 1. 论文对象与判断

**论文对象是完整 RCAPS；V4 是当前实现版本。V3 是历史内部实现，在已核验等价的配置中可对应同时关闭 S/T 的条件。**

现在已经有完整系统外部比较、最终系统内 M2/M3/S/T 对照和一部分机制证据。问题不是只有 V3→V4 的增量，而是报告仍先讲增量，容易把工作三误认成全文贡献。

主问题应固定为：**RCAPS 如何结合异构放置、实时选路和执行整形，在已测资源与负载下改善服务质量，其工作量代价和适用边界是什么？**

工作三建议定位为“面向 Decode 聚合与传输阻塞的时空执行整形”。这是对已实现决策与机制的概括，不代表已经证明独立首创、全局最优或普适正协同。

## 2. 三个工作点与代码关系

| 工作点 | 模块 | 决定什么 | 代码入口 | 边界 |
|---|---|---|---|---|
| 工作一：异构部署与合法执行空间 | M1 + M2 | GPU 层段、复制结构、合法连接 | `rcaps/v3/resource_graph.py`、`topology.py`、`placement.py`、`search.py` | M1 是合法性基础；M2 是有界启发式搜索 |
| 工作二：实时资源感知选路 | M3 | 新请求走哪条完整路径 | `rcaps/v3/queue_cost.py`、`online_scheduler.py`、`routing.py`、`scheduler.py` | 源端为 Prompt 选路，后续 Decode 固定会话路径 |
| 工作三：时空执行整形 | S + T | 开放哪些合法边，长传输何时让出资源 | `rcaps/v4/admission.py`、`chunking.py` | S 静态、T 固定字节块长，无反馈优化器 |
| 测量设施 | 固定窗口 + 被动探针 | 端到端、batch、GPU 工作、网络等待 | `benchmarks/fixed_window.py`、`rcaps/v4/probe.py` | 探针不是额外性能算法 |

实际执行关系：

```text
物理资源与画像
  → M1 合法性表示 + M2 放置
  → 已部署层兼容 DAG
  → S 静态边准入
  → M3 为新会话选择完整路径
  → GPU 执行 / T 对合格链路上的 Prompt 传输分块让出
  → 被动记录端到端与机制指标
```

S 在选路前、T 在传输执行时，不能简单将工作三画成 M3 后的独立串行阶段；当前也没有“测量后在线更新准入图”的反馈环。

`benchmarks/registry.py` 的 `MAIN_METHOD` 已是 `rcaps_v4`。`rcaps/v4_method.py` 复用 V3 布局，并由 `evaluate_variant()` 组装 S/T 和探针。保留 `v3` 代码目录不影响 V4 是完整实现，没有必要为论文命名而复制冻结代码。注册表顶层 docstring 等旧措辞可在后续非冻结发布中清理。

### M1：合法性与可达性

`layer_dag()` 检查连续层段、层容量、物理链路和完整路径。层段 `[s_i,e_i)` 到 `[s_j,e_j)` 的边满足 `s_j ≤ e_i < e_j`，完成层边界严格增加，因此物理网络可有环，执行图仍无环。

`placement.validate()` 还检查副本覆盖、节点不复用、规范副本前后向可达性及 KV 容量为正。论文适合给出合法性推导、导出与运行图一致性、非法放置拒绝检查和适用范围，不应通过关闭约束构造性能消融。**KV 容量为正并不保证任意并发负载下不溢出；图合法性也不等于模型输出质量或真实硬件推理正确性证明。**

### M2：静态有界搜索

最多两个分支边界；C1 单集群选出 `1→4→3`，三集群选出 `1→3`。目标为归一化静态 TTFT、TPOT 和瓶颈需求的加权和，权重 0.40/0.35/0.25，需求中的 Decode 代价权重为 8。规范路径、均匀分流是代理假设，不是直接优化在线 P95。

搜索有共同阶段及扩展阶段的预算上限，实际评估数并非总是相同：单集群完整/受限布局记录为 752/376 次，三集群均为 997 次。应报告预算和提前停止规则，不能声称所有条件实际计算量完全相等。

### M3：有效实现是可加代价路由

有效 `_route()` 位于 `queue_cost.WorkloadQueueDagScheduler`，不是直接采用 `routing.py` 中较早的最早完成时间递推。代价包括 Prompt 服务、GPU/链路等待、活跃会话 Decode 服务及传输时间；最终单 token Decode 项含与模拟器画像一致的 2 倍修正。

`online_scheduler.py` 已有就绪 Decode 优先和同跳传输合并，这两点不是工作三首次加入。`static` 对照关闭实时等待与活跃会话项，保留合法性与既有执行规则；应称静态状态对照，不是移除整个 M3。当前没有逐 token 重选路或 KV 迁移。

## 3. 工作三的准确定位

### 研究矛盾

更多合法路径能提供绕开慢链路的机会，也可能分散会话、削弱 Decode 聚合。收窄空间有助于聚合，却可能集中网络竞争；已有 Decode 优先规则也无法中断已经开始的长 Prompt 传输。

工作三因此回答：**给在线路由器多大的可选空间？给长 Prompt 一次多长的连续传输占用？**

### S：保留规范结构的静态边准入

实际规则来自 `admission.py`：

1. 从部署副本链构建规范边 `E_can`，检查属于完整合法图且存在完整路径。
2. 找到带宽不超过 `50,000,000 B/s` 的规范 GPU–GPU 边，记起点集合 A、终点集合 B。
3. 从完整图额外保留带宽高于阈值、且起点在 A 或终点在 B 的非规范 GPU–GPU 边。
4. `E_adm = E_can ∪ E_detour`；M3 在准入图内实时选路。

这是局部拓扑启发式，代码没有逐边在线收益估计，也没证明每条新增边一定改善目标。50 MB/s 是十进制字节速率，不是 50 Mb/s。

构造满足 `E_can ⊆ E_adm ⊆ E_full`；规范图可达时，准入图保留至少一条合法完整路径。该性质可作为设计保证，性能提升不能由此推出。这里“准入”是路径/边准入，不是拒绝到达请求，也不是直接锁定 Decode batch 大小。

### T：固定块长的传输让出

仅处理计算节点间的 Prompt 激活传输；默认作用于带宽不超过 50 MB/s 的链路，块长 `4,194,304 B = 4 MiB`。块结束释放链路和两端 NIC 带宽，既有调度器获得发送就绪 Decode 的机会，随后资源可用时续传。

路由不变，全部字节发完并经过一次传播延迟后下游才收到请求。它不是计算层 chunked prefill、KV 迁移或边传边计算。实际块发送时间由获配带宽决定，不能把 `4 MiB / 标称带宽` 当端到端延迟保证。当前也没有完整的逐块软件/协议固定开销模型。

### 推荐表述与新颖性边界

章节名：**面向 Decode 聚合与传输阻塞的时空执行整形**。

英文描述：**Topology-constrained path admission and prompt-transfer yielding**。不必额外造一个系统缩写。

可用段落：

> 在异构放置与资源感知路由之上，RCAPS 进一步调节执行路径的开放范围和长 Prompt 传输的连续占用。空间层保留部署的规范副本连接，并以静态拓扑规则选择性开放高速跨副本边；时间层对慢计算链路上的 Prompt 激活传输进行固定粒度分块，在块边界为就绪 Decode 提供发送机会。两层分别作用于会话分散与传输阻塞，其条件收益、交互和资源代价通过完整系统消融与机制观测评价。

MoLink 的[官方摘要](https://aclanthology.org/2025.findings-emnlp.957/)明确包含 Prefill 传输分块、Prefill/Decode 调度和即时块长决定。本轮核对了该摘要，尚非全面查新，也没有复现 MoLink。不能将传输分块本身包装为首创；可讨论的差异是路径准入决策、与放置/在线路由的结合及条件机制证据。独立创新强度仍需最近系统的完整比较。

## 4. 已完成范围与指标

离线审计重新通过：**120 个去重成功窗口、122 次尝试、2 次保留失败**。93 格主批次加 27 格外部批次，经恢复补齐；原 halted 状态保留。43 组可用 V4 对照中 42 组齐全三种子，历史 Helix 三集群负载 400 只有两个成功种子。

历史曲线另复用 71 个经身份/执行等价审核的成功结果，同条件新结果优先；不能简单加成独立样本数量，也不能声称全部窗口首次成功。

协议：seed 0/1/2、1800 秒、零预热、不排空；Helix 离散事件模拟器。下表绝对值为三种子均值，标准差与单值见[新审计 JSON](RCAPS_V4_OVERVIEW_AUDIT_20261026.json)及[原数值报告](../experiments/v4_paper/RESULTS_CN.md)。百分比逐种子计算 `RCAPS/对照−1` 后取均值。

TPOT 是请求内已观测 Decode 间隔均值的跨请求 P95，不等于逐 token ITL P95，也不只涵盖完整完成请求。GPU s/token 是忙碌工作量，不是能耗或 GPU 数量。负载包含输入和目标输出 token，输出吞吐只统计实际生成 token，二者不能相除当完成率。

## 6. 最终系统内的模块消融

| 问题 | 现有条件 | 控制条件 | 可解释内容 |
|---|---|---|---|
| M2 | `v4` vs `single_boundary`，单/700、三/320 | 同池、轨迹、M3、S/T 规则与参数 | 替换放置方案在最终栈内的条件效果 |
| M3 | `v4` vs `static`，同锚点 | 同放置、S/T、执行规则 | 实时等待/会话信息相对静态状态的效果 |
| S | `v4` vs `temporal`，三/160、320 | 同 M2/M3/T | 稀疏图相对完整图的效果 |
| S 的空间选择 | `canonical4/v4/temporal`，三/320 | 同 M2/M3、慢链路 4 MiB T | 规范/稀疏/完整图折中 |
| T | `v4` vs `spatial`，三/160、320 | 同 M2/M3/S | 分块相对不分块的效果 |
| T 的范围与粒度 | `all4`；`chunk1/2/v4/chunk8`，三/320 | 同稀疏图与其他模块 | 当前单拓扑/负载的敏感性 |

应从完整系统比较 `v4` 对 `temporal/spatial`，仅比较“加 S 对 V3”“加 T 对 V3”不够。M2 改变放置后，按相同 S 规则重建图是必要下游响应，不应要求不同部署使用相同绝对边集。

### M2 的证据与代价

单集群完整布局 `1→4→3`，受限布局 `1→2`，都使用 24 GPU，但总层副本数为 147/112。RCAPS 的 TPOT 约低 31.49%，GPU s/token 约高 173.48%，完成率为 94.05%/91.38%。这是放置策略的条件收益与代价，不是固定副本容量下“多一个边界”的纯效应。

三集群两者都为 `1→3`，节点顺序与层分配不同，并非同一布局；均为 23 个活跃 GPU、144 个层副本。RCAPS 的 TPOT 约高 0.16%，没有稳定优势。该场景没有选出多级结构，不能作为多级机制的正向证据，也不能仅凭宽度相同就认定等价。

应标作 restricted M2 / single-boundary placement，不是 w/o M2。若要证明 M2 相对一般外部放置的收益，旧 V3 证据可作背景，但不能直接改名为 V4；最终条件下需定义外部放置的规范图接口。

### M3 的服务收益与工作量代价

相对静态状态，TPOT 在单/700、三/320 分别下降约 59.94%、31.47%，GPU s/token 却增加约 303.23%、256.78%。单集群完成率由 85.05% 到 94.05%，积压由 192 到 76.33；三集群完成率由 89.07% 到 92.29%，积压由 63.33 到 44.67。

静态路由的低 GPU 工作不能脱离积压与完成度评价，RCAPS 也不能声称对所有组件替换都减少工作量。

### S/T 的条件收益及敏感性

三/320 固定 T：稀疏图相对完整图，TPOT 降约 2.98%、GPU 工作降约 28.01%、TTFT 增约 0.90%。固定 S：分块使 TPOT 降约 14.92%，GPU 工作增约 3.38%。

相对规范图+T，RCAPS 的 TPOT 低约 8.92%、TTFT 低约 17.17%，GPU 工作高约 70.20%。这是保留绕行能力的折中，不是全指标支配规范图。

4 MiB 相对 1/2 MiB 的 TPOT 高约 5.40%/4.40%，工作量略低；相对 8 MiB 的 TPOT 低约 3.57%，工作量略高。全计算链路分块在该点 TPOT 略好于仅慢链路。**4 MiB 是冻结折中，慢链路范围是设计选择，均未证明最优。**

## 7. 机制、交互与无效条件

三集群/320 四格建议改用论文条件名，代码版本只作为追溯字段：

| 条件 | 代码标签 | 实际路径数 | token 加权 Decode batch | Decode 网络等待总量 s | P95 TPOT s | GPU s/token |
|---|---|---:|---:|---:|---:|---:|
| RCAPS − S − T | `v3` | 33 | 6.80 | 7546.94 | 0.69902 | 0.08957 |
| RCAPS − T | `spatial` | 8 | 9.66 | 8013.08 | 0.71165 | 0.06293 |
| RCAPS − S | `temporal` | 31 | 6.58 | 2593.09 | 0.62397 | 0.09037 |
| 完整 RCAPS | `v4` | 8 | 9.21 | 2777.85 | 0.60540 | 0.06505 |

路径数是实际使用量，不是理论可达路径数；等待是多消息多链路累计值，可超过窗口长度。batch 是层执行观测的 token 加权汇总，不是端到端请求批大小。

- S → 路径集中 → Decode batch 增大 → Decode GPU 工作减少。但单独 S 在 320 的 TPOT 增约 1.81%，不能声称无条件降低延迟。
- T → 块间让出 → 观测到的 Decode 等待下降 → TPOT 改善；并未同样大幅降低 GPU 工作。
- 两者在该点兼顾聚合与网络等待，收益不可相加；其作用维度不同。

320 的 TPOT 对数交互项三种子均负，160 符号不一致。支持条件性互补，不支持普适超加性或统计显著协同。该四格解释工作三，不替代 M2/M3 消融。

探针在消息开始发送时结算等待，窗口结束尚未发送的等待没有全部进入此总量。Prompt 占用重叠不是严格因果分摊，发送/接收 NIC 重叠不能相加。更强机制归因需末端未发送等待、单位工作量归一化或反事实补充。

单集群、C2、C3 的正式记录没有合格慢链路，T 不发生分块，主要检验 S。C2 TPOT 平均变化约 −0.41%，种子方向不一致；C3 约 +0.33%，各种子均略退化；GPU 工作分别下降约 73.15%/32.74%。不能将工作量收益写成稳定尾延迟收益，也不能以此证明 T 的跨网络泛化。

## 8. 主张—证据矩阵及补强顺序

| 主张 | 当前证据 | 缺口/限定 | 优先级 |
|---|---|---|---|
| 完整 RCAPS 优于外部方法 | 两共同点含三外部基线，Helix 多负载 | Swarm/SP 缺关键高负载；明示基线实现及调优范围 | 高 |
| M2/M3 在最终系统有价值 | 两拓扑最终条件对照 | M2 改变层副本容量、三集群未激活多级；M3 有工作量代价 | 高，先解释已有数据 |
| S 保持聚合、T 缓解阻塞 | 四格与层执行/链路记录 | 未完全闭合因果分摊、窗口残留等待 | 中高 |
| 跨网络/负载形态适用 | C1 两拓扑、C2/C3 工作量证据 | T 主要仅一个三集群网络激活；带宽/RTT/长度/突发性不足 | 高，取决于主张 |
| GPU 工作收益可迁移 | 多池模拟结果 | `model.py` 对 singleton Decode 时间乘 2，需公共画像反事实或独立画像 | 中高 |
| 实现可复核 | 清单、请求记录、等价检查、失败保留 | 原生崩溃及历史 TypeError 未定位，需独立稳定环境复核 | 高 |
| 真实低开销、节能、扩容 | 无直接证据 | 缺逐块开销、功率积分、SLO 容量与真实多 GPU 验证 | 不主张或另补 |
| 工作三独立新颖 | 准入实现和条件机制已有 | 分块已有近邻方案，最近系统与全面查新不足 | 高，措辞克制 |

建议顺序：

1. **重排已有结果**：外部比较 → 最终模块对照 → 机制交互 → 参数与泛化 → 版本历史附录。无需为此重跑 120 格。
2. **补关键外部负载**：若要主张覆盖锚点，Swarm/SP × 单/700、三/320 × 三种子，最小新增 12 格；仍不等于全负载曲线。失败保留，不填零、不静默换种子。
3. **收紧模块解释**：现有 M2 对照可证明策略替换的条件效果；只有主张纯边界收益时才需匹配副本/容量。不要关闭 M1 或强行隐藏不可行组合来凑矩阵。
4. **最小网络/画像稳健性**：分别改变带宽、S 阈值、T 阈值；先固定放置隔离因素。公共取消 singleton 倍率或替换画像须一致作用于所有对照，并建立新实验身份。
5. **按主张补截尾和实现代价**：固定到达前缀的长窗口/完整生命周期；真实或有开销模型的块间让出。共同完成子集不能代替所有到达请求的服务质量。

本轮只整理优先级，没有自动启动新增实验。

## 9. 贡献与论文结构

建议三个工作点，M1 并入第一点作为基础：

1. 异构资源约束下的层兼容表示与共享/复制分段有界放置，为服务提供可执行结构。
2. 给定部署内利用实时 GPU、链路和会话状态选路，并保持会话路径约束。
3. 静态路径准入与传输让出调节会话分散和连续占用，通过完整系统消融揭示条件收益及代价。

这些描述实际工作内容；新颖性仍需相关工作论证，不能由版本新增或性能改善自动推出。

| 1 | 平台、负载、指标、公平性 | 仿真边界、轨迹、负载定义和截尾 |
