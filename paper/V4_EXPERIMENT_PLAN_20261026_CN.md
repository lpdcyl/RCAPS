## 1. 结论与版本边界

建议形成一个完整 V4：**冻结 V3 的合法图表示、放置搜索和在线路由，加上静态稀疏边准入与慢链路固定 4 MiB Prompt 激活传输分块。** 正文以 V4 为主方法，V3 为最重要的内部基线。工作三必须进入统一执行入口，不能只把独立工作三结果改名成 V4。

V4 的执行链为：M1 合法图表示 → M2 放置 → 静态准入图 → M3 在线请求选路及 Decode 路径绑定 → 慢链路传输分块。时间控制位于执行层，空间控制位于选路之前；两者与原有 M2/M3 组成完整系统。

不把已经失败或尚未闭环的动态路径掩码、等待凑批、CABR、自适应块长、KV 准入控制等同时并入本版，否则无法隔离工作三的贡献。根目录 `PLAN_V4.md` 是此前另一条设计路线的历史计划，本文件另存，不覆盖它。

## 2. 两层干扰控制应当怎样表述

| 层次 | 控制对象与实现 | 应证明的机制 | 不宜宣称 |
|---|---|---|---|
| 空间层 | 给定放置后，保留规范副本边，并按静态慢链路端点规则准入少量高速跨副本边；M3 在准入图内选路 | 减少路径分散，缓解 Decode 合批碎片化，降低单位输出 GPU 忙碌工作；必要绕行保留网络弹性 | 空间隔离、全局最优稀疏图、所有资源池尾延迟都降低 |
| 时间层 | 对物理带宽 ≤ 50,000,000 B/s 的计算链路，将 Prompt 激活传输切为 4,194,304 字节块，块间释放链路/NIC 并给已就绪 Decode 发送机会 | 缩短长 Prompt 传输造成的连续占用，降低 Decode 等待和尾延迟 | 新发明 Decode 优先级、计算层 chunked prefill、所有阻塞严格界于 4 MiB/B、4 MiB 普适最优 |

推荐论文表述：**面向异构流水线的空间与时间两层干扰控制：通过拓扑约束的静态路径准入减少执行分散，并通过带宽受限链路上的分块发送缓解阶段间传输阻塞。**

“互补”是当前合适的主张；“协同增益”须由正式二因素实验支持。已有开发实验交互项两种子异号，尚不能证明稳定超加性。时间干扰也不能限定为跨集群独有：本地新单集群诊断的初步原始值复算，在判定负载 600 下，k1 的 Prompt 零传输干预使 TPOT 平均下降约 10.36%，冻结 V3 布局约 1.97%；完整审计和正式报告尚需补齐。

- **规范图 vs 稀疏图 vs 完整图**：在三集群 320、相同放置/M3、均启用慢链路 4 MiB 下比较。稀疏与完整已在 E2，新增规范图 3 格。检验保留绕行边是否仍必要；需要时补规范图不分块，区分网络绕行与时间控制。

- 不要求把四条绕行边的所有子集正式重跑。已有开发单边删除和边增补失败可进附录，当前重点是保留必要绕行这一设计原则。

### E4：最终 V4 条件下保留 M2/M3 的贡献

- **M2**：完整放置搜索 vs 单边界受限放置，均使用同一 M3、准入规则和分块。C1 两拓扑各 3 格，至多新增 6 格；如果某拓扑两者导出的完整布局及规范边完全一致，就标记机制未激活并复用，不能把重复执行当消融证据。
- **M3**：固定 V4 放置、准入和分块，将实时状态路由替换为既有静态状态路由，C1 两拓扑各 3 格，新增 6 格。若正文专门主张活跃会话项，再加 no-session 条件。
- 不为 M1 制造性能消融；M1 是合法性表示，应验证可达性和执行正确性。不要同时移除放置、准入、路由来声称某单一模块贡献。
- 原有 Helix 放置 × RCAPS 调度交叉实验在部分条件 KV 失败，不能隐瞒或强行复跑成完整成功矩阵。若将 Helix 放置接入准入层，必须事先定义规范图的生成规则，不能按结果选择规范路径。

### E5：4 MiB 的折中与机制链条

固定稀疏图、慢链路范围，在三集群 320 比较块长 **1、2、4、8 MiB、无分块**，共 15 个逻辑窗口。4 MiB/无分块已在 E2，新增 1/2/8 MiB 共 9 格。主张是冻结默认值在已测条件的折中，不根据正式曲线把获胜块长回填成预先选择。

机制记录应嵌入 E2/E3/E5 的窗口，避免再跑独立大矩阵：

| 机制链 | 必需观测 |
|---|---|
| 准入 → 路径集中 → 合批 → GPU 工作 | 实际路径/边使用分布；逐 GPU Decode 批大小分布与 singleton 占比；按 token 加权批大小；Prompt/Decode 工作分解；每输出 token 的执行次数及实际层段工作 |
| 分块 → 连续占用缩短 → Decode 等待 → TPOT | 按阶段/链路记录消息大小、逐块序列化时长、排队等待、NIC 争用、Decode 被 Prompt 占用阻挡比例、端到端 TPOT |

路径数减少不是合批改善的充分证据；必须展示中间指标。分块按字节限制每次发送量，实际阻塞还取决于获得的带宽、排队和 NIC，不能直接把 4 MiB/B 当端到端上界。

## 6. P2：正式论文应补的稳健性与泛化

P1 解决“完整方法是否有效、两层是否各有作用”，本节解决“结果是否依赖特定拓扑/画像/窗口”。避免把所有因素做无目的的全笛卡尔积。

| 实验 | 建议最小设计 | 要回答的问题 |
|---|---|---|
| 资源池泛化 | C2 负载 160、C3 负载 400，V4 vs V3，0/1/2；V4 新增 6 格，旧对照审计 | 稀疏空间控制的收益能否迁移；无慢链路时组合是否保持等价 |
| 网络条件 | C1 三集群选 3–4 个带宽档，覆盖默认慢链路阈值两侧，比较 V3、S、V4 | 时间层何时有效，静态准入何时改变；先固定放置隔离网络作用，再把重新规划作为另一问题 |
| 阈值 | 依据现有物理带宽分布选取能实际改变边集的阈值；准入阈值与分块选择阈值分别变化 | 50 MB/s 是否是偶然调参；不能同时改变两种阈值后归因于其中之一 |
| 长度/到达模式 | 至少增加一种长 Prompt 条件和一种长 Decode 或突发到达条件；同一比较共享请求轨迹 | 分块收益及合批节省是否只在默认工作负载成立；变更长度与到达规律分开进行 |
| 画像依赖 | 对所有比较方法一致取消模拟器的 singleton Decode 额外倍率，或采用独立实测服务曲线；V3/S/V4、两个拓扑锚点、0/1/2 | 空间层 GPU 工作收益是否主要来自 `model.py` 对 batch=1 的时间翻倍；这是模型反事实，不冒充硬件结果 |
| 窗口/样本偏差 | 主协议不变；对固定到达前缀补完整生命周期或统一更长观测，再比较全体与共同完成请求 | 尾延迟改善是否来自完成样本组成、起止窗口或积压转移 |
| 运行开销 | 规划、建准入图、在线选路、分块事件分别计时；同环境串行重复测量 | 静态准入成本与时间控制开销；墙钟重复不是新增独立工作负载种子 |

长度分布必须检查画像支持区间、节点 token/KV 容量，不能静默截断超限请求。网络变化必须同时修改物理输入和仿真网络，避免规划图与运行图不同。窗口稳健性也不能只挑共同完成请求得出全体用户改善，需同时报告未完成请求及等待情况。

42 节点实验是 **42 个逻辑计算节点、64 张物理 GPU**，不是 42 张 GPU。既有 1450 负载结果可在身份及无作用等价性检查后复用；2150 负载的 V3/准入 KV 失败必须保留。后来的 31 节点/53 GPU 候选改变了布局和准入条件，不能当作同一 V4 的免费泛化。只有正文主张规模泛化时，才把该规模的集成 V4 正式检查列为必做。

若目标是以实际系统落地为主要贡献的论文，建议至少增加小型真实多 GPU/网络链路验证，测量分块开销和阻塞变化。当前模拟器没有完整的逐块协议/软件开销，仿真收益不能直接写成硬件收益；若暂时没有硬件条件，就明确论文的仿真研究边界，并补逐块开销敏感性。

## 8. 指标、统计和复用规则

- 正式结果始终展示 seed 0/1/2 单值、均值与标准差，以及同轨迹逐种子相对变化。三种子不足以支持强统计显著性主张；请求级重采样也不能替代独立运行数。
- 当前 TPOT 是“请求在窗口内已观测 Decode 间隔的均值，再对请求取 P95”；不是所有 token 间隔直接取 P95，也不是只对全部完成请求统计。正文明确其定义，如需 ITL P95 另行记录逐 token 时间戳。
- TTFT 对齐首个输出 token；不要将 Prompt 完成时刻与首个 Decode 完成时刻混为同一口径。
- GPU 秒/输出 token 包含 Prompt 与 Decode 忙碌工作，是服务工作量指标，不等于耗电、碳排或部署 GPU 数量减少。若要主张能源收益，必须补能耗模型/测量。
- offered token/s 包含输入和目标输出；输出吞吐只含实际输出，二者不能相除称为完成率或利用率。
- 主结果同时公开 TTFT、吞吐、完成率、积压，不以 TPOT 或 GPU 单指标覆盖退化。历史 +5% 等护栏只属于原协议，不是新负载下的保证；新实验在运行前写清主要指标与失败判据。
- 可复用条件：算法与模拟器行为等价、完整物理/画像/布局/数据/轨迹身份匹配、窗口和指标一致、执行记录完整。若只补无扰动计量，旧端到端数值可留但机制计量仍需新证据；若改变共同执行语义，则相关对照一并重做。

## 9. 推荐执行顺序与论文呈现

1. P0：整理 V4 统一入口、定位执行异常、修正探针、冻结协议及身份清单。
2. 先做 E2 在三集群 320 的正式四格及关键机制采样，确认新增组件的独立贡献与代价可解释。
3. 扩展 E1 整体负载曲线和共同负载五方法比较，同时补 E2 的 160 条件。
4. 补 E3/E4/E5：规范图、分块范围、最终条件下 M2/M3、块长敏感性。
5. 补 P2 的资源池、网络/工作负载、画像与窗口稳健性；按论文主张决定大规模和硬件验证范围。

这些组应合并成按身份去重的执行清单：相同条件只运行一次，被多个图表引用。表内“逻辑窗口数”不能直接相加当作实际运行数；旧对照能复用多少，取决于 P0 审计结果和最终修复影响范围，当前不承诺固定总运行时长。

正文建议依次呈现：V4 整体负载曲线 → 五方法主表 → 两层 2×2 消融 → 空间/时间机制图 → 参数与跨条件稳健性。V3 放在正文核心对照中，历史开发路线、其他种子、负结果和详细执行审计放附录，保持证据可追溯。

最终目标是回答：**完整 V4 在同等资源与工作负载下有什么收益；空间层与时间层分别贡献什么；保留原 M2/M3 为什么仍必要；收益在什么条件成立、在什么条件退化。** 不需要把所有 V3 历史实验原封不动重跑一遍，但最终系统主结果和关键条件消融必须以统一 V4 为对象。
