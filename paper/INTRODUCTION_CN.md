# 1 引言（中文初稿）

在由不同型号 GPU 和跨区域链路组成的集群中，部署一个无法由单台设备完整容纳的大语言模型，需要将模型层分配到多台设备，并为每个请求选择覆盖全部层的执行路径。同一请求的各阶段必须依次完成，但多个请求又会争用 GPU、链路和 KV 缓存。因此，某条路径的性能既取决于其静态计算与传输代价，也取决于请求到达时资源上的未完成工作。面向这种异构环境，[HexGen](https://proceedings.mlr.press/v235/jiang24f.html) 展示了非对称模型划分的价值；[Helix](https://www.cs.cmu.edu/~rvinayak/papers/Helix_ASPLOS_2025_Serving_LLMs_over_Heterogeneous_GPUs_and_Network_via_Max_Flow.pdf) 则通过最大流与混合整数规划，联合设计模型放置和逐请求流水线。

现有方法已说明，放置和路由不能只按 GPU 算力或单条链路的带宽分别决定。Helix 的容量图刻画了异构 GPU 与网络对长期服务吞吐的共同限制，其在线调度在 KV 缓存容量约束下主要沿规划得到的流量份额选择路径；然而，容量相近的路径在请求到达时可能有不同的排队状态，固定份额也不能直接表示某个请求将遇到的等待。[Sun 等人](https://ece.iisc.ac.in/~parimal/papers/2025/peva.pdf) 已将等待、通信和计算代价纳入跨地域模型块服务的在线最短路，说明“考虑等待后选路”本身并非新的算法。对于异构 GPU 流水线，本文聚焦一个具体问题：**如何通过模型放置与在线请求调度，协调异构计算和网络资源，在有限显存下提供可选择的执行路径，并降低运行时资源竞争与尾延迟？**

这一问题包含三个相互关联的挑战：异构 GPU 的显存与算力如何同非均匀网络匹配；有限显存如何在模型层共享、复制和路径灵活性之间分配；已有多条合法路径时，如何避免新请求集中到繁忙资源。我们据此提出 **RCAPS**（Resource Contention-Aware Placement and Scheduling），将拓扑与容量约束下的模型放置、结构化多路径构造和在线状态感知路由结合起来。

RCAPS 在离线阶段将计算、传输和等待表示为带有请求依赖与资源依赖的事件有向无环图，通过最长完成链及路径集合需求估计关键资源。放置器在显存容量和物理链路约束下，以**共享前缀和两条各自覆盖剩余模型层的后缀**构造初始层放置，并针对关键资源调整前缀边界、相邻层划分及设备顺序。这一结构是受约束的搜索起点；导出的层兼容图还包含满足层连续性和物理连接条件的跨后缀拼接边，因此在线请求并不限于两条固定路线。请求到达时，调度器读取 GPU、链路队列和活跃 KV 会话的当前状态，在层兼容图上以等待、传输及计算工作量为代价选择提示阶段路径；后续解码复用该路径，并合并同一链路上已经就绪的解码传输。离线放置采用启发式局部细化，不声称获得全局最优。

我们在 Helix 事件仿真器中，以相同拓扑、请求轨迹和固定测量窗口，将 RCAPS 与原版 Helix 的放置及最大流调度进行端到端配对比较。在单集群与三集群的官方负载下，三个种子的逐种子相对变化均值显示：RCAPS 的输出吞吐分别提高 **8.67%** 和 **18.85%**，P95 首 token 时延（TTFT）分别降低 **34.28%** 和 **54.26%**，P95 输出 token 间隔（TPOT）分别降低 **54.22%** 和 **70.06%**。这些数字描述的是**完整系统**相对 Helix 的仿真结果；单个组件的效果由固定放置或固定调度的受控实验另行评估，三个种子不支持统计显著性结论。

嵌套放置消融进一步表明，机制贡献随拓扑而变：在三集群中，拓扑感知初始化相对仅容量布局带来主要放置收益，后续关键资源细化的吞吐增量较小且未呈现稳定的尾延迟改善；在单集群中，仅容量与拓扑粗布局相同，关键资源细化则带来一致的增量。因此我们不将关键资源反馈表述为所有场景中的主要性能来源。

本文围绕上述三个挑战组织方法与证据：

1. **异构资源匹配：**在显存可行性约束下，结合物理拓扑、设备能力与链路代价构造层放置。事件图、路径集合需求及关键资源局部搜索用于评估和细化放置；三集群中拓扑初始化相对仅容量布局的受控增量支持该环节。
2. **共享与复制结构：**使用共享前缀、两条完整后缀和合法拼接边构建多路径空间。结构消融显示这一整套设计相对单条完整路径的综合效果；对照同时改变了副本量、每请求经过的设备数及路径选择数，不能把收益全部归因于路径冗余，也不意味着该固定骨架最优。
3. **动态资源竞争：**在层兼容 DAG 上依据当前 GPU、链路工作量及活跃 KV 会话负担选择请求路径，已就绪解码传输合并属于执行层优化。完整调度模块与各消融的贡献分别报告，不将端到端增益归给某一项调度代价。

上述证据目前限于两种已测拓扑的事件仿真；种子 1 曾参与开发调参，真实 GPU 与网络环境中的性能仍需进一步验证。
