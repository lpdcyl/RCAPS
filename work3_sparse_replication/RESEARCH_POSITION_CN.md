# 第三个工作点：当前可成立的研究定位

## 核心问题

给定异构 GPU 放置及合法的层兼容 DAG，**应向在线路由器暴露哪些边**，
才能在单集群控制 Decode 路径碎片化，同时在多集群保留绕开慢链路的通道？
路径空间本身是系统资源决策；“合法边越多越好”没有实验支持。

## 三个工作点的接口

1. **放置与执行图**：把异构 GPU、网络和模型层映射为合法放置与层兼容 DAG。
   M1 主要保证表示与合法性，M2 在其上搜索放置；M1 不单独宣称性能收益。
2. **在线路径选择**：给定已准入的 DAG，M3 用实时 GPU、链路及活跃会话状态
   为新请求选一条完整路径，Decode 保持路径绑定。
3. **路径空间准入**：在放置图与在线路由之间，保留规范副本边，
   只开放能绕过慢规范边的高速跨副本边。规范边永远保留，故不破坏合法路径存在性。
   第三工作决定在线路由能选什么；第二工作决定在该集合中选哪条。

闭环是：资源与放置 → 合法 DAG → 拓扑约束边集 → 在线选路 →
实际链路竞争、Decode 批次和尾延迟 → 验证边集设计。

## 已核实的结果与可写主张

- 完整 DAG 相比规范路径，在相同放置与轨迹下单集群 TPOT 变差，
  三集群却改善；T2 诊断确认路径增多伴随 Decode 批次碎片化，
  慢链路干预又确认多集群网络收益是重要因素。
- 既有门控方法在单集群不开放额外边，在三集群只增加 4 条高速绕行边。
  本目录独立重跑 6 个 1800 秒正式候选窗口，六格 TPOT 相对变化与历史报告
  逐格完全一致。单集群三个种子 TPOT 分别改善 8.63%、9.62%、10.13%，
  吞吐均略增；三集群均值 TPOT 高 1.81%、吞吐低 0.03%，按**原协议的
  三种子均值规则**达到 +2% TPOT / −0.5% 吞吐非劣效边界。
- 将各 GPU 的固定窗口忙碌比例之和除以输出 token/s，得到窗口内 GPU
  忙碌秒/输出 token。C1 单集群三种子均值下降 45.87%，三集群下降 29.73%；
  此项是对已完成 C1 结果的事后补充分析。
- 在未用门控方法跑过正式窗口的 C2/C3 上，先用短窗口登记失败与方向，
  再**单独冻结** GPU 工作量正式协议。1800 秒、种子 0/1/2、原规则不调参：
  C2 单位 GPU 工作平均下降 73.15%，全体 TPOT 平均下降 0.41%，吞吐升 0.34%；
  C3 单位 GPU 工作平均下降 32.74%，全体 TPOT 平均上升 0.33%，吞吐升 0.01%。
  两池均通过登记的 GPU 工作量、延迟、共同完成请求、吞吐和完成率联合门槛。
  历史 V3 对照存在执行源码哈希差异，已在当前运行时逐格重跑；六格轨迹、路由、
  GPU 忙碌、请求级样本及主指标均与历史文件相同，重算门槛仍通过。
- 新试的无拟合链路外部代价在两条开发轨迹未通过联合门槛；
  不将其包装成第三工作的有效方法。

因此当前最稳妥的论文表述是：**在已测的四种异构放置/资源池中，拓扑约束的
路径空间准入减少了单位输出的 GPU 忙碌工作；C1 单集群改善尾部 Decode 延迟，
C1 三集群保留了接近完整 DAG 的吞吐和延迟，C2/C3 的正式长窗口也满足登记的
服务性能护栏。** 这里没有统计显著性主张。

## 不能写成的结论

- 不能写“第三方法在所有拓扑都优于 V3”。三集群三个种子的全体 TPOT
  均略高于 V3，种子 2 高 3.76%，共同完成请求高约 3.96%。
- 不能写“证明动态路径切换必要”或“链路外部代价在线有效”。这两条的
  既有开发/反事实证据没有通过独立联合门槛。
- 不能写“统计意义上的非劣效保证”。原判定是三种子均值阈值，
  未给出能够覆盖 +2% 界限的置信区间；这个界限是在更严格开发门槛失败后
  重新注册的，历史过程需如实披露。
- 不能把 C2/C3 的资源效率主指标说成最初就预定的论文终点。它是在 C1 与
  C2/C3 短窗口发现资源效率信号后注册，再用此前未跑过门控候选的
  C2/C3 正式种子验证；短窗口 C2 的全体 TPOT 一格曾恶化 10.51%。
- 不能写“已在真实 GPU 集群验证”或“已证明方法新颖”。全部是 Helix
  离散事件仿真；Helix 已研究异构图上的放置与请求调度，MoLink 已研究
  Prompt/Decode 在慢链路上的传输冲突。

## 论文级边界与下一步

1. **方法自身的机制归因**：在门控路径上直接计量逐 GPU Decode 批大小、
   GPU 忙碌秒/token、慢链路 Prompt/Decode 阻挡；现有 T2 和慢链路诊断
   分别解释两端，单位 GPU 工作也已直接测得，但尚未逐节点证明
   门控方法的全部收益都来自批次同步。
2. **独立新颖性核查与强基线**：逐篇核对图剪枝、多路径流水线和 batching
   的最新论文，并在同布局、同在线调度器下与简单阈值、规范路径和完整 DAG
   对照。当前 C2/C3 没有慢链路，门控方法等于规范路径，因此网络门控本身
   只有 C1 三集群一个正式拓扑的检验。
3. **真实系统或独立模拟器**：当前全部结论依赖 Helix 离散事件模型，
   应用到真实集群仍需外部效度验证。

这份定位完成了问题→方法→冻结协议→独立长窗口→同运行时对照的**仿真证据闭环**；
论文层面的独立新颖性与真实系统外部效度仍需单独核查。
