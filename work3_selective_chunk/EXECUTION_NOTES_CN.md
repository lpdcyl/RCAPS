# 运行过程说明

首次 60 秒烟测使用三个并行进程时，门控基线子进程在没有 Python 异常
记录的情况下退出，父进程收到 `BrokenProcessPool`。同次烟测的
`slow_noop` 与 `chunk_slow` 两格已完成。保留当时的空门控日志；
随后使用同一冻结审计、相同种子 143 和配置，以单进程补跑门控基线。
门控与 `slow_noop` 的轨迹、请求样本、路由、吞吐、延迟和 GPU 忙碌
逐项相同。开发与后续正式窗口均以已完成的结果判定；首次进程故障
不折算为性能结果。

旧分块 hook 的 `treatment` 摘要文字固定为 `prompt_chunk_1MiB`；
4 MiB 结果实际使用的字节数由每格 `chunk_bytes=4194304`、冻结协议和
`formal_report.py` 的断言核对。该文字问题不影响仿真传输计算。
