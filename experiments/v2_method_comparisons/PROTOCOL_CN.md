# V2 三项完整方法替换对照：冻结协议

## 对照边界

V2 实现及两份正式布局不改动。三组各把一项**完整方法**替换为同功能方法，另两项保持 V2：

| 组 | 简单替代 | 较强替代 | 完整 V2 |
| --- | --- | --- | --- |
| M1 建模评价 | 仅显存容量与物理连通性的完整放置流程 | 静态异构模型完成整轮 V2 结构搜索：GPU Prefill/Decode、传播与传输代价、六请求的静态资源需求；没有请求间事件依赖 | 六请求事件 DAG 建模完成整轮搜索 |
| M2 自适应放置 | 固定一张共享 A100、12 层前缀、两后缀的放置方法 | 宽度 4、最多 16 轮的有界 beam search；与 V2 共用初始可行结构、合法邻域、事件 DAG 评价器，候选评价总上限等于该拓扑 V2 原正式搜索（single 112，multi 319） | V2 自适应共享复制搜索 |
| M3 在线调度 | 规范合法路径轮转，逐请求传输 | 对每个 Prompt 根据当前 GPU／链路待完成工作量，估计三条规范完整路径的 Prefill 完成时间并选最短；Decode 固定路径，逐请求传输 | 在完整层兼容 DAG 上动态选路，合并就绪 Decode 传输 |

所有放置共享显存容量、层连续覆盖与真实物理连通性硬约束。M1 的完整替代范围为**离线评价及其驱动的放置决策**；在线调度所必需的合法执行图仍由同一布局导出。M2 三种方法使用原 M1 事件 DAG 和 V2 在线调度。M3 三种方法使用字节相同的 V2 正式布局。各差额只在这两个保留方法的条件下解释，不跨表相加。

## 正式协议与复用

- 70B、两种原始 24-GPU 物理拓扑；single 700、multi 320 提供 token/s，输入和目标输出均计入提供负载。种子 0/1/2，1800 秒零预热，窗口尾不排空；吞吐只计完成请求的输出 token。
- 开发检查仅用种子 100/101：先 60 秒，再 300 秒高负载；不根据正式种子调整规则。正式运行起始并行度 2。
- 简单替代和完整 V2 的已存正式窗口只有在布局、物理拓扑、轨迹哈希、请求身份、种子与协议字段全部通过报告脚本审计后才复用。新方法结果、日志和布局均写入本目录。
- 如果某一组的任一策略高负载窗口失败，保留该窗口日志；该组三种策略在预定共同低负载 single 350、multi 160 重新以相同三种子评测，不把低负载指标填进高负载表。

## 报告与判断

每个配置报告三种子的绝对吞吐、P95 TTFT、P95 TPOT、完成率和窗口末积压的均值 ± 样本标准差。完整 V2 相对替代方法的百分比先逐种子配对再汇总；共同可观测请求的两项 P95 另列。M1 报告候选排序与单候选评价时间，M2 报告搜索评价数、规划时间和最终结构，M3 报告路径使用与 GPU／出站等待。失败窗口不产生完整窗口指标；若两种方法选出执行语义相同布局，记录来源并报告零增量，不制造差异。

Helix 是外部整系统基线，使用已有高负载同轨迹主表；Swarm/SP 与 V2/Helix 的四方法同负载比较使用已有 single 350、multi 160 的独立补充表。各方法自身压力实验也单列，不与本组替换对照跨负载相减。三个种子只描述波动，不支持显著性或真实集群性能声明。
