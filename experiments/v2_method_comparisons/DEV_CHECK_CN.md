# 三项完整方法替换：开发检查

开发检查只使用种子 100/101，两种 24-GPU 拓扑和正式提供负载。三个新增替代方法各运行一次 60 秒短窗口及一次 300 秒压力窗口：每一档均 **12/12 个窗口正常结束**。全部结果、日志分别保存在 `smoke/` 和 `stress/`；这些窗口不计入正式三种子均值，不用于调节算法规则。

新增静态模型与 beam search 布局分别通过 `audit_layouts.audit()` 的 24-GPU 覆盖、层连续性、显存/KV 容量、物理边带宽及时延核验。两个新布局在两种拓扑上均与正式 V2 布局的结构和层分配不完全相同，因此需要独立正式评测。

| 拓扑 | 静态模型：共享层/后缀 | beam search：共享层/后缀 | V2：共享层/后缀 |
| --- | ---: | ---: | ---: |
| 单集群 | 48 / 2 | 48 / 3 | 48 / 3 |
| 三集群 | 48 / 3 | 48 / 3 | 48 / 3 |

上述检查证明配置可执行，不保证 1800 秒正式窗口一定完成或具有较好性能。正式失败窗口仍保留日志并标记为不完整。
