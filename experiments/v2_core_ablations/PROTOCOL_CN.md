# RCAPS V2 三项方法级消融：冻结协议

## 研究对象与统一运行条件

三组消融分别考察建模评价、共享复制结构搜索、在线路由决策。V2 算法与两份正式布局保持不变。在线正式窗口统一使用 70B、原两种 24-GPU 物理拓扑、单集群 700／三集群 320 提供 token/s、种子 0/1/2、1800 秒、零预热、窗口尾不排空。提供负载是输入与目标输出 token 之和；吞吐是已完成的输出 token/s。开发检查只用种子 100/101。所有新增文件留在本目录，不覆盖既有正式记录。

每张表都报告输出吞吐、P95 TTFT、P95 TPOT、完成率、窗口末积压（逐种子完整窗口值的均值 ± 样本标准差）。失败窗口保留日志与状态，不计算缺失值。不同方法在同拓扑、同负载、同种子必须有相同轨迹哈希和请求身份。三个种子只描述波动，不做显著性声明。

## Table A：建模评价

只在**同一份冻结候选布局集合**上替换评价器，最终在线执行都用原 V2 调度器。候选池由 V2 确定性初始候选、其一步合法邻域和原 V2 正式布局构成；生成过程本身仍含 V2 的设备排序和层分配启发式，因此本表仅归因于**给定候选池内的评价与选择**，不能宣称完全去除了异构信息。

1. `Compute-only`：对规范路径的 GPU Prefill／Decode 服务时间分别取最慢路径，再按 V2 的 0.40／0.35 权重对参考值归一化；不计链路和请求间依赖。
2. `Compute + Communication`：在同一静态路径计算上加上传播和激活传输时间；不模拟请求间资源串行依赖。
3. `Event DAG`：原 V2 六请求事件图与 0.40／0.35／0.25 目标。

三个评价器均对**每个候选**打分；分数先保留九位小数比较，以免浮点舍入差异伪造优劣，同分时优先现有 V2 正式布局，其后按布局签名排序。`Event DAG` 在这张表中指“V2 评价器在共同候选池中选型”；只有其选择的布局和现有 V2 正式布局字节、执行语义一致时，才可复用 V2 正式在线结果，否则须单独运行。该表不是三种放置搜索算法的比较。

解释性验证：从同一候选池按结构族的确定性签名抽取若干布局，使用开发种子 100/101 的 600 秒同负载窗口，报告各评价器得分与实际输出吞吐、P95 TTFT、P95 TPOT 排序的一致性。三个目标分别报告，不事后拼凑一个有利的综合指标。报告候选数、布局重合、打分开销与评分排序；若实际窗口失败，保留失败记录，不把它当作完整窗口尾延迟。

## Table B：自适应放置

所有配置使用 V2 原事件 DAG 评价器、16 步局部搜索上限和 V2 在线调度器。

1. `Fixed Structure`：现有一张 A100、12 层共享前缀、两后缀的 V2 固定结构搜索。
2. `Fixed Branches`：共享 GPU 数和共享层边界仍可搜索，仅将后缀数量限制为二；与 V2 使用相同的候选生成、评分和局部邻域规则。
3. `Full Adaptive`：现有 V2 完整自适应搜索与正式布局。

复用前审计现有固定结构与 V2 的拓扑、布局、轨迹和协议。报告每种结构的总模型层副本数，以及共享前缀 GPU 的排队等待；等待总量须结合完成率与积压解释，不能单独叫作瓶颈贡献率。

## Table C：在线调度

三种策略使用**字节相同的 V2 正式布局**，保持 GPU 本地执行批次规则和就绪 Decode 传输合并一致，仅改变请求入场时的合法 DAG 路径代价。

1. `Static DAG`：在完整层兼容 DAG 上按 GPU 服务和物理链路传输代价选路，不读取实时 GPU／链路未完成工作量或活跃 KV 会话数。
2. `Queue-Aware DAG`：加上实时 GPU／链路未完成工作量，仍不使用活跃 KV 会话代价。
3. `Full V2`：原 V2 调度器，加入活跃 KV 会话代价。

这张表因三种策略均保留 Decode 传输合并，结论只归于**路径评分中的运行时信息**，不能将差额归因于传输合并。报告 GPU 排队请求秒／到达请求数和出站等待请求秒／到达请求数；后者包括发送端和下游限制，不称纯链路排队。

## 失败与补充负载

先以种子 100/101 做短窗口合法性与可运行性检查。正式高负载的任一策略若因 KV 容量或无法路由失败，仍保留高负载失败；另在预先指定的共同低负载（单集群 350、三集群 160）对该表全部策略运行相同三种子，以获得完整且公平的补充对照。不能只降低失败策略的负载，也不能用低负载数值填补高负载表格。
