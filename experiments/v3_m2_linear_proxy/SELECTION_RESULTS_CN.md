# 新 LP 与 V3 加权目标：部署选择在线对照

## 问题与协议

本实验检验离线评价器**选出的部署**在固定 M3 下是否更好，不要求离线分数与在线 P95 数值相等。

- 候选池在评分前固定：发布版 V3、搜索敏感性实验的六个布局、已有容量搜索导出的三个布局、已有联合候选的三个布局；相同部署哈希合并后，单集群 8 个、三集群 10 个。没有根据本次在线结果生成新候选。
- 两种方法面对同一候选池。旧目标为冻结 V3 的 `objective(measure())`；新目标为四类工作负载的固定到达率最小服务时间 LP。新 LP 的类别频率来自开发种子 100、300 秒的高负载轨迹。精确并列时优先发布版 V3，再按路径稳定排序。
- 在线调度均为未修改的 `GraphModeledQueueAwareDagScheduler`，使用 1800 秒固定窗口、种子 0／1／2。每种拓扑测原协议的低／高两档负载。旧目标所选布局复用哈希匹配的正式结果；LP 所选布局新跑。12 对结果逐一核对部署文件哈希与请求轨迹哈希。
- 本方法在已有正式结果被查看后设计，且候选池来自既有实验；因此这是透明的回顾性机制验证，**不能作为独立留出样本的显著性证据**。三个种子只显示方向与波动。

`selection_manifest.json` 是运行前固定的候选、分数、选择结果和输入哈希；`formal_manifest.json` 是 12 对原始结果的路径与哈希；`selection_results.json` 是逐种子及平均差值。复现命令：

```powershell
python -m experiments.v3_m2_linear_proxy.select
python -m experiments.v3_m2_linear_proxy.validate_selection smoke
python -m experiments.v3_m2_linear_proxy.validate_selection formal --workers 4
python -m experiments.v3_m2_linear_proxy.validate_selection report
```

## 选出的部署

| 拓扑 | 原加权目标 | 新 LP |
| --- | --- | --- |
| C1 单集群 | 发布版 V3 `[1,4,3]` | `capacity_3` `[1,3,2]` |
| C1 三集群 | `beam64_budget1000` `[1,3]` | `capacity_1` `[1,3]` |

单集群 LP 布局的旧静态分数为 0.7380，高于原目标所选布局的 0.7084；新 LP 的服务时间下界为 12.2075 秒／请求，低于原目标所选布局的 12.3129 秒／请求。三集群 LP 布局的旧静态分数为 0.9699，高于原目标所选布局的 0.8944；新 LP 下界为 47.0419 秒／请求，低于原目标所选布局的 47.0829 秒／请求。两种代理确实导致不同部署决定。

## 固定 M3 在线结果

下表是三个种子的平均值；Δ 为 **LP 所选布局减去加权目标所选布局**。吞吐／完成率越高越好，TTFT／TPOT／积压越低越好。

| 拓扑 | offered token/s | Δ吞吐 token/s | ΔP95 TTFT s | ΔP95 TPOT s | Δ完成率 | Δ末端积压 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 单集群 | 350 | +0.049 | -0.009 | +0.007 | +0.0016 | -1.0 |
| 单集群 | 700 | -0.063 | -0.014 | +0.016 | -0.0021 | +2.7 |
| 三集群 | 160 | +0.019 | +0.025 | -0.015 | -0.0035 | +1.0 |
| 三集群 | 320 | -0.019 | -0.005 | +0.029 | +0.0023 | -1.3 |

在两拓扑的高负载下，LP 所选布局的 P95 TPOT 分别高 **2.85%** 和 **4.16%**，且各自三个种子的 TPOT 差值方向均为不利。单集群高负载的吞吐与完成率也均略低。三集群低负载的 TPOT 则低 **2.62%**，但 TTFT 与完成率略差。TTFT 的逐种子方向在所有设置中均不完全一致。

另外将 LP 所选布局直接与**发布版 V3** 对照：三集群 320 负载下，LP 的平均 P95 TTFT 高 **0.152 秒**、P95 TPOT 高 **0.023 秒**，吞吐低 **0.029 token/s**；三集群 160 负载下 TTFT 低 0.011 秒、TPOT 低 0.024 秒。该结论同样表现为负载相关，不能用低负载收益概括高负载。完整逐种子差值见 `selection_results.json` 的 `paired_deltas_linear_minus_released_v3`。

## 判定

**新 LP 没有表现出稳定的在线部署选择收益，当前不应替换 V3 M2 目标。** 这不是因为离线分数必须等于在线 P95，而是因为相同候选池、固定 M3 的部署决定在高负载下没有改善目标表现。最大流／最小服务时间类模型可作为容量可行性筛选或结构诊断，但不能单凭“形式上是线性规划”解决手工权重的合理性质疑。

若要去掉手工权重，更有依据的方向是先明确服务目标（例如 TTFT、TPOT 上限与吞吐优先级），把它写成约束和词典序选择，再用独立的部署选择实验检验。不能根据本次三个正式种子的结果反向调系数并把它们当作新的留出验证。
