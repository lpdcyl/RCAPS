# V3 M2 静态目标的合理性：答辩口径与证据边界

## 可以直接向导师解释的版本

> M2 的任务是在请求到来之前，从容量与链路约束下选一个可执行的分段复制部署；M3 的任务是在部署固定以后，根据实时队列和 KV 状态给每个请求选路径。离线阶段看不到未来的排队轨迹，因此不应要求 M2 的静态分数等于在线 P95。V3 的静态目标是部署搜索的**筛选代理**：用规范路径的最坏 Prompt / Decode 服务时间约束串行延迟，用均匀分流的最大资源需求避免明显瓶颈。三项都按同一个参考部署归一化，再用 0.40 / 0.35 / 0.25 表达延迟与容量的设计偏好。权重不是从理论推导出的唯一最优值；我们用 Pareto、权重敏感性和固定 M3 的在线消融检查这个选择是否导致脆弱或无效的部署决定。

这里的关键是把**数值一致**与**决策有效**分开。静态服务时间没有动态排队、实际批处理和 M3 的路径流量，不能预测在线 P95 的绝对值；它仍可能筛掉高通信或高瓶颈的部署。最终主张以固定同一 M3 后的在线 TTFT、TPOT、吞吐、完成率和积压为准。

## 代码中究竟优化了什么

对可行部署 $x$，`measure()` 计算三个量：

- $C_f(x)$：规范完整路径上的最大 Prompt 计算加传输时间。
- $C_p(x)$：规范完整路径上的最大 Decode 计算加传输时间。
- $C_b(x)$：请求在物理可达后继之间均分时，GPU / 链路的最大加权服务需求；其中 Decode 需求乘以固定系数 8。

`objective()` 使用参考部署的同类量 $C_i(x_{ref})$，最小化

$$J(x)=0.40\frac{C_f(x)}{C_f(x_{ref})}+0.35\frac{C_p(x)}{C_p(x_{ref})}+0.25\frac{C_b(x)}{C_b(x_{ref})}.$$

参考值使秒数不同量级的三项可比较；**归一化本身不能证明 0.40 / 0.35 / 0.25 是最佳偏好**。$C_b$ 中的均分也只是低成本近似，不能声称等于 M3 的真实分流。这些事实来自 [冻结代码](../../rcaps/v3/placement.py)；M2 的有界搜索还在候选生成阶段使用近似排序，因此下述固定池重评分不代表“重新运行搜索后必然相同”。

## 新做的权重与 Pareto 审计

使用 [LP 对照前固定的候选清单](selection_manifest.json)：单集群 8 个、三集群 10 个不同部署哈希。逐个重算三个归一化分量并核对原静态分数，按步长 0.05 枚举非负且和为 1 的 231 组权重；其中 19 组满足每项与默认权重相差不超过 0.10。并列时优先发布版 V3，规则与原候选选择一致。原始逐候选数据和胜出计数在 [objective_audit.json](objective_audit.json)，复现命令为 `python -m experiments.v3_m2_linear_proxy.objective_audit`。

| 拓扑 | 默认权重选出的部署 | 默认部署在静态 Pareto 前沿 | 附近 19 组仍选默认部署 | 整个网格仍选默认部署 | 第二个不同分数的差距 |
| --- | --- | --- | ---: | ---: | ---: |
| 单集群 | 发布版 V3 | 是 | 19 / 19 | 192 / 231 | 0.002953 |
| 三集群 | `beam64_budget1000` | 是 | 19 / 19 | 180 / 231 | 0.001988 |

在单集群，默认部署的归一化三元组是 `(0.726316, 0.693696, 0.700304)`，加权贡献依次是 `(0.290527, 0.242794, 0.175076)`。另一类 Pareto 解 `capacity_3` 将 TTFT / TPOT 分量降至 `(0.705232, 0.690365)`，却使瓶颈分量升至 `0.857143`。单集群前沿有 5 个部署哈希，但只有 **2 个不同的三元组**；默认组的四个不同部署哈希拥有相同静态三元组。

在三集群，默认权重下的固定池最优解 `beam64_budget1000` 三元组为 `(1.063505, 0.852877, 0.681818)`；另一前沿解 `beam128_budget1000` 为 `(1.066490, 0.863310, 0.676692)`。后者仅改善瓶颈分量，前两项都较差。注意：三集群**发布版** V3 是搜索预算 500 的结果，而固定池最优解来自预算 1000；不能把后者称为发布版 V3 的实际输出。

**解读边界：** 19 / 19 只说明“在这个既有候选池、0.05 离散网格、各分量 ±0.10 的邻域内选择稳定”；231 组计数也不是概率或全局鲁棒性。两个默认部署都在**静态三目标**的 Pareto 前沿，不能推出在线 Pareto 最优。特别是三集群的分数间距很小，连续权重空间的切换边界值得承认。候选池与正式结果已在此前工作中查看过，所以这是回顾性诊断，不是独立留出验证。

## 固定 M3 的在线证据与反例

[M2 主消融](../v3_m2_paper_ablation/RESULTS_CN.md) 在同一 M3、同一轨迹和种子 0 / 1 / 2 下，把完整 M2 放置同 Helix ILP 放置比较：单集群和三集群高负载的平均输出吞吐分别提高 4.76% 和 9.32%，P95 TTFT 分别降低 2.222 秒和 5.090 秒。这支持**M2 放置机制在已测条件下有效**，不能单独证明权重组合最优。

[搜索敏感性结果](../v3_search_sensitivity/FINDINGS_CN.md) 也暴露静态与在线排序不一致：三集群把搜索预算从 500 增至 1000、Beam 保持 64 时，静态分数降低，但高负载平均 P95 TTFT 相对发布版升高 0.157 秒。固定池的另一个 Pareto 解 `beam128_budget1000` 相对 `beam64_budget1000` 在三集群 320 token/s 下，平均 P95 TTFT 从 5.484 升至 6.437 秒，P95 TPOT 从 0.694 升至 0.764 秒，吞吐从 70.566 降至 70.260 token/s；这是三种子均值，不能宣称统计显著。

[新 LP 对照](SELECTION_RESULTS_CN.md) 用同一候选池和固定 M3 替换评价器，选出不同布局，但在两种拓扑的高负载下，LP 布局的平均 P95 TPOT 分别恶化 2.85% 和 4.16%。这说明“换成线性规划”本身并不能消除部署目标与在线结果之间的差距。

## 可能的质疑及准确回答

**质疑 1：离线指标和在线 P95 不一样，目标函数是否不合理？**

答：两者层级不同。离线评估的是部署可提供的服务结构和资源压力；在线 P95 还由到达波动、队列、动态批处理、KV 与 M3 决定。要求绝对数值一致不合理。合理的验证是：固定 M3，用同一负载和轨迹比较不同部署的在线结果，并检查代理选型的敏感性。我们已做这两类检查，同时如实报告三集群排序反例；因此只主张**有用的低成本部署代理**，不主张准确预测在线尾延迟。

**质疑 2：0.40 / 0.35 / 0.25 是否拍脑袋？**

答：它们是未从 SLO 推导的设计偏好，确实有主观性。归一化防止单位和尺度直接支配目标；固定池的邻域扫描显示默认部署对小幅权重变化不敏感，并且位于静态 Pareto 前沿。证据仅支持“当前结果并非依赖一个精确的权重点”，不能支持“这些系数理论最优”。若需完全消除偏好参数，应先给出应用的 TTFT / TPOT SLO 与吞吐优先级，再做约束或词典序选型，并在独立负载上验证；当前仓库没有这样的预定义 SLO，不能事后按三个正式种子倒推阈值。

**质疑 3：M2 与 M3 没有使用同一条路径分布，是否自相矛盾？**

答：存在建模间隙，但不构成执行不一致。M2 输出合法部署与 DAG；M3 只在该 DAG 内按实时状态选路径。均分假设用于低成本资源压力估计，并非 M3 的路由承诺。准确说法是“部署搜索与在线调度通过可执行 DAG 耦合，但静态分流模型没有显式预测 M3 流量”。排序反例表明这个间隙是方法局限，也是未来研究动机。

## 与既有系统论文的关系

[Helix](https://www.cs.cmu.edu/~rvinayak/papers/Helix_ASPLOS_2025_Serving_LLMs_over_Heterogeneous_GPUs_and_Network_via_Max_Flow.pdf) 使用离线最大流 / MILP 处理异构 GPU 与网络，再由运行时分配请求；[DistServe](https://www.usenix.org/conference/osdi24/presentation/zhong-yinmin) 根据 TTFT / TPOT 要求规划资源，运行时仍需实际调度；[AlpaServe](https://arxiv.org/html/2302.11665) 也区分部署规划与运行时调度。这些工作支持“离线规划不必输出在线 P95 的相同数值”这一设计范式，但**不能替 V3 证明具体权重或均分假设正确**。V3 的独特论点仍应落在可变分段边界、共享前段与后段复制、异构资源下的可达 DAG，以及固定 M3 的部署消融上。

## 结论

目前最稳妥的表述是：**V3 M2 使用可解释、计算便宜、对局部权重扰动稳定的静态多目标代理来搜索特殊的分段复制结构；其有效性由固定 M3 的在线放置消融支持。代理与在线排序确有偏差，权重没有理论最优保证。** 不应把 0.40 / 0.35 / 0.25 包装为严格推导的新算法，也不应声称 M2 直接优化在线 P95。
