# V3 M2 搜索敏感性：结论

两种 C1 拓扑各测试六组参数。每组在独立进程中使用相同初始布局、参考布局、静态目标和 M3。默认 `Beam=64、每阶段预算=500` 的评分及部署哈希与冻结 V3 完全一致。10 个不同部署都通过 60 秒检查；48 个新正式窗口全部成功，12 个发布版窗口经审计复用。同负载同种子的到达轨迹一致。

## 单集群

默认评分为 **0.708396**，已是六组中的最低值。Beam 32／64／128 在预算 500 下得到相同评分和宏观结构 `[1,4,3]`、边界 `[48,51]`；GPU 分配有差异，但在 350 和 700 offered token/s 下，三个种子的吞吐、P95 TTFT／TPOT、完成率和积压与默认值逐项相同。预算增至 1000 也未改善评分或在线指标。

预算降至 250 时，布局退回单边界 `[1,2]`；评分高 **0.417%**。相对默认设置，在 700 offered token/s 下输出吞吐平均低 **0.604 token/s**，P95 TTFT 高 **0.283 s**，P95 TPOT 高 **0.041 s**。因此默认预算对该池有实际作用，更大的预算在已测范围内没有额外收益。

## 三集群

六组都保持单边界 `[1,3]`、边界 48，但微观 GPU 分配各不相同。默认评分 **0.902849**；预算 1000、Beam 64 得到本次最低分 **0.894364**，默认比它高 **0.949%**。不过在 320 offered token/s 下，预算 1000 相对默认的 P95 TTFT 平均高 **0.157 s**，P95 TPOT 低 **0.005 s**，输出吞吐低 **0.009 token/s**。静态目标改善并未转化为一致的在线改进。

Beam 128、预算 500 的静态分数也低于默认，但在 320 offered token/s 下，平均吞吐低 **0.269 token/s**、P95 TTFT 高 **0.998 s**、P95 TPOT 高 **0.058 s**；Beam 128、预算 1000 的尾延迟退化更大。Beam 32、预算 500 的在线指标接近默认，160 负载下 P95 TPOT 平均低 **0.010 s**，320 负载下低 **0.003 s**，但 P95 TTFT 在两档负载中方向不同。

## 论文表述边界

可以说明 V3 的确定性搜索在单集群的已测参数范围内表现稳健，默认预算避免了低预算造成的结构退化。三集群默认设置并非本次扫描中的静态最低分，但在线表现与部分低分布局相当，且明显优于两组 Beam 128 布局的尾延迟。**不能声称增加 Beam 或预算单调提升在线性能，更不能据此声称全局最优。** 静态代理分数与在线尾延迟存在排序不一致，这一点应在方法局限中如实讨论。三个种子仅描述波动，不支持统计显著性声明。
