# 70B 放置与在线调度交叉实验

## 比较协议

四格中第一个字母表示放置，第二个字母表示在线调度：`H` 为 Helix，`R` 为 RCAPS。`HH` 与 `RR` 使用已有的固定窗口结果，`HR` 与 `RH` 用 `run_cross.py` 在相同设置下重新仿真。每个拓扑使用种子 0、1、2；窗口 1800 秒，预热 0 秒；单集群负载 700 token/s，三集群 320 token/s。四格使用同一套 24 张 GPU 和底层物理拓扑；导出的可用逻辑链路由各自放置决定。`cross_summary.json` 核对两种放置的设备类型、显存和 NIC 等硬件参数一致，并核对导出的每条链路都存在于对应物理拓扑且带宽、时延一致。同一种子的请求轨迹哈希一致；同一放置的方案与仿真配置哈希一致。

| 代号 | 放置 | 在线调度 |
| --- | --- | --- |
| HH | Helix ILP | Helix max-flow |
| HR | Helix ILP | RCAPS queue-aware DAG |
| RH | RCAPS | Helix max-flow |
| RR | RCAPS | RCAPS queue-aware DAG |

放置改变了模型层占用，因此每台设备剩余的 KV 缓存容量也可能改变；这是放置作用的一部分。单集群导出的逻辑边数为 Helix 31、RCAPS 47；三集群为 Helix 25、RCAPS 47，均经过物理链路核验。

## 分开的条件收益

主分解使用三种子齐全的路径 `HH → HR → RR`：先固定 Helix 放置只换调度，再固定 RCAPS 调度只换放置。每个百分比使用该比较起点的三种子均值作为分母；两段的百分比不直接相加。

| 拓扑 | 固定放置改调度：HH → HR | 固定调度改放置：HR → RR | 总方案：HH → RR |
| --- | --- | --- | --- |
| 单集群吞吐 | +6.624 token/s（+4.66%） | +5.714 token/s（+3.84%） | +12.339 token/s（+8.67%） |
| 单集群 p95 TTFT | 降 0.772 秒（11.75%） | 降 1.481 秒（25.53%） | 降 2.254 秒（34.28%） |
| 单集群 p95 TPOT | 降 0.605 秒/token（35.49%） | 降 0.320 秒/token（29.05%） | 降 0.925 秒/token（54.23%） |
| 三集群吞吐 | +6.305 token/s（+10.82%） | +4.674 token/s（+7.24%） | +10.979 token/s（+18.85%） |
| 三集群 p95 TTFT | 降 5.167 秒（33.15%） | 降 3.291 秒（31.59%） | 降 8.457 秒（54.27%） |
| 三集群 p95 TPOT | 降 1.321 秒/token（41.34%） | 降 0.918 秒/token（48.97%） | 降 2.238 秒/token（70.07%） |

这证明当前总方案的收益并非只来自放置或只来自调度：两次单因素替换在两个拓扑、三个种子的吞吐、TTFT 和 TPOT 上均朝改善方向变化。这里的“放置收益”有明确条件——保持 RCAPS 调度器；“调度收益”保持 Helix 放置。不能把它们宣称为与另一组件无关的固定贡献比例。

三集群的完整四格还揭示交互。固定 Helix 调度器时，`HH → RH` 平均增加 9.073 token/s；固定 RCAPS 调度器时，`HR → RR` 增加 4.674 token/s。两种放置与调度的吞吐收益有重叠，四格交互项为 **−4.399 token/s**。固定 RCAPS 放置时，`RH → RR` 只增加 1.906 token/s，p95 TPOT 降 0.247 秒/token，**p95 TTFT 反而增加 0.293 秒**。因此，不应写成“RCAPS 在线调度在任何放置和指标上都更好”。单集群 `RH` 缺一个种子，完整四格交互仅能作为种子 0、2 的探索性观察。

## 解释边界

本实验将“完整 RCAPS 放置”与“完整 RCAPS 在线调度”分开，并未单独隔离放置中的事件图、关键资源筛选、拓扑初始化等机制；它们要结合实验 A、静态无事件图消融解释。三个种子只提供配对一致性，不支持统计显著性表述。两种拓扑采用不同负载，所以只在各拓扑内部比较四格，跨拓扑只描述观察到的机制。

复现命令与实现见 [README.md](README.md)。机器可读逐种子与效应数据见 [cross_summary.json](cross_summary.json)，图见 [cross_factorial.png](figures/cross_factorial.png)。
