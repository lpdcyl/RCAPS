# E4：WSL2 真实 TCP 栈上的队头阻塞微基准

登记日期：2026-10-29；本目录尚无正式网络测量。由用户在本机 WSL2 运行。实验使用 Linux network namespace、veth 和内核 netem qdisc；它不是真实物理 NIC、跨机 WAN 或 GPU 集群验证。

输入来自已审计的 experiments/v6_completion/bandwidth_threshold/formal/runs/B12p5_T50/sparse_chunk/seed0/result.json。预先固定挑选规则：在内部 Compute→Compute 链路中，筛选 10–20 MB/s、有 Prompt 与 Decode 消息的链路，取 Decode 消息数最多者；当前为 Compute-4→Compute-20，Decode 69109/1800 s，Prompt 279/1800 s，名义链路容量 13.2 MB/s。原结果仅有每链路消息计数、没有逐消息时间戳；因此从原 584 个请求到达时间用固定规划种子 20261029 抽取 279 个 Prompt 代理到达，取预定 [600,630) s 的 30 s 段。每轮 Decode 到达按上述实测平均速率和固定随机种子生成指数间隔。此序列是受审计汇总约束的流量代理，不冒充真实链路逐包抓包。

大消息 12,300,000 B，小消息 16,384 B。链路单向延迟 25 ms，速率分别 12.5、25、50 MB/s；发送 veth 施加 netem，ACK 反向不整形。模式为单 TCP 连接 FIFO 不分块、单连接 Decode 优先不分块、单连接 Decode 优先 4 MiB/1 MiB 分块、两条 TCP 连接分别承载大/小消息。所有模式使用同一轮相同的大小消息到达时间。每模式×速率 10 轮，共 150 次 30 s 测量；不加入可选 gRPC/HTTP2。每连接固定小发送缓冲，避免应用瞬间把全部大消息塞入内核使分块边界无效。

在 WSL2 标准库 Python3 下执行。每轮记录小消息端到端时延均值/P95/P99、大消息完成时延、接收字节、tc 发送字节和链路利用率；原始逐消息时延压缩保存。用同一输入序列计算理想串行（不可抢占/按块抢占）与双流公平共享预测，逐模式报告预测与实测 P95 差异。每轮结束确保大小消息全部送达；失败写独立 failure.json，不填零、不覆盖。结果只作为虚拟链路 Linux TCP 栈对应用层队头阻塞的证据，网络模型误差只对这里的消息序列和条件成立。

仓库根目录 RCAPS_审稿补充实验清单_v2.md 的 E4 是本方案来源；本方案的额外固定选链、抽样和 30 s 片段规则是因为现有结果缺乏逐链路事件时间戳，论文必须显式披露这些代理假设。
