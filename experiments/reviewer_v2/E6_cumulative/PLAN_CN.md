# E6 机制逐项叠加：预注册方案

登记于 2026-11-01，任何 E6 新窗口结果产生前。目标是回答审稿人对“放置、空间准入、会话路由、传输分块是否只分别叠加”的疑问。这里的主输出是**顺序配置差异**，不预设单调改善，也不把顺序差异直接解释成与加入顺序无关的主效应或超加性协同。

## 六级配置及必要的路由迁移控制

| 级别 | 部署 | 路由 | 稀疏准入 S | 会话持续代价 | 慢链路 Prompt 4 MiB 分块 T | 证据来源 |
|---|---|---|---|---|---|---|
| H0 | 原 Helix | Helix+ MaxFlow | 否 | 否 | 否 | V5 核心 HHplus |
| P1 | RCAPS | Helix+ MaxFlow | 否 | 否 | 否 | V5 核心 RHplus；只改部署 |
| R2 | RCAPS | RCAPS DAG | 否 | 否 | 否 | E6 新窗口；显式控制路由器迁移 |
| S3 | RCAPS | RCAPS DAG | 是 | 否 | 否 | E6 新窗口；相对 R2 只改 S |
| Q4 | RCAPS | RCAPS DAG | 是 | 是 | 否 | E6 新窗口；相对 S3 只改会话持续代价 |
| T5 | RCAPS | RCAPS DAG | 是 | 是 | 是 | V5 核心 V4；相对 Q4 只改 T |

五步简图中“+空间准入”若直接接在 P1 后，会把 MaxFlow→RCAPS DAG 路由器更换混在一起。因此插入 R2 作为必要控制。P1→R2 应写成“路由器迁移”，不能当作纯会话项；只有 S3→Q4 隔离会话项。完整 H0→T5 的效果不是各步相对百分比之和。

## 冻结口径与验收

- 70B 画像驱动 CPU 仿真，C1 single/350、single/700、multi/160、multi/320；seed0–4；1800 s、零预热、不排空。相同拓扑/负载/seed 的流量轨迹必须一致。所有新条件均使用 RCAPS 既有布局，冻结其 solution.ini、simulator_cluster.ini、placement.json 与物理池文件。
- H0、P1、T5 从 V5 核心已审计 120/120 批次按明确键复用，逐项核对结果 SHA、轨迹、部署、口径；旧结果不覆盖。R2/S3/Q4 新增 3×4×5=60 个正式窗口。
- 新窗口共用原 v4 AdmissionScheduler、PromptTransferChunkHook、MechanismProbe、固定窗口驱动和资源计量；单独验证 R2 与既有无 S/T 的 RR 在关闭会话代价之前的差别确实只来自会话项。
- 各级逐种子记录 P95 TPOT、P95 TTFT、GPU 秒/token、固定窗口完成率、吞吐与失败。仅成功 5/5 且轨迹/部署可配对时报告均值与 t(4) 95% 配对区间；失败原件留存、独立重放另记，绝不把失败填零或改写旧正式批次。
- 在正式运行前记录源码、部署、物理池、画像、旧结果、环境和预设配置 SHA256，先 60 s 冒烟验证每个新级别可达和指标存在；通过后登记正式 manifest。新条件在已运行的失败键重跑与 E4 网络测量旁以最多一个 E6 worker 执行，避免覆盖任何现有队列。
- 论文主张仅限受测配置与顺序；真 GPU 集群及物理链路未验证。
