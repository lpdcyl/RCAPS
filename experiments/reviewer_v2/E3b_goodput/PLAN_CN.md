# E3b：逐请求 SLO goodput 负载扫描预注册

登记日期：2026-10-30（Asia/Seoul），正式结果产生前。继承 RCAPS_审稿补充实验清单_v2.md 的独立协议：先预热 300 s，随后测量到达窗口 1800 s；停止新到达后，测量窗口请求排空至全部完成或最多额外 3600 s。只统计测量窗口到达的请求；尾部未完成保留右删失状态，goodput 计零贡献，不把失败请求延迟填零。固定请求轨迹由拓扑、负载、种子决定，同条件五种方法完全一致。

五方法：完整 RCAPS；RCAPS-batch（沿用 v6_completion/session_cost.py 已冻结 batch 会话代价变体，不改放置、稀疏准入、4 MiB 慢链路分块或执行器）；原 Helix；Helix+；E2a_helix_tuning 经部署纠错后的 Helix-tuned。Helix 三个方法固定同一官方 Helix 部署，RCAPS 两个方法固定同一 V4 部署。E2a 两个主负载在各拓扑内恰好选中相同配置，故扫描新增负载沿用该拓扑配置：单集群 priority+batch、KV (0.8,0.4)；三集群仅 priority、KV (0.9,0.6)。不以 E3b seed0–4 重新选参。

负载：single 350、500、700、900 token/s；multi 160、240、320、400 token/s。正式注册 5 方法 × 8 负载 × seed0–4 = 200 窗口。主指标对每个已完成的测量请求分别判定 TTFT ≤ T1 且该请求全输出平均 TPOT ≤ T2；合格请求输出 token 总数除以固定 1800 s 得 goodput token/s。请求输出长度不足 2、缺首 token 或截止时未完成时，不能确认双指标合格，计非合格并在分母总到达数中保留。另报告 goodput / 实际载入模型的 GPU 数（token/s/GPU），及合格输出 token 总数 / 从测量起点到实际排空停止点的全部 GPU 忙碌秒（token/GPU-busy-s）。忙碌秒包含该时段内所有竞争工作，含未结束的预热请求；不把总物理池 GPU 数当作已部署 GPU 数。

阈值在运行前固定如下：

| 档位 | single (T1, T2) | multi (T1, T2) |
|---|---|---|
