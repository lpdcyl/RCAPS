# E1：替代放置的结构消融预注册

登记日期：2026-10-29；尚未生成正式结果或启动窗口。V4 seed3/4 独立重放及五种子审计现已完成。使用 70B C1_single/C1_multi 的原物理池和画像，所有变体固定完整 RCAPS 的在线路由、稀疏准入、4 MiB 慢链路分块和统一执行规则。每个拓扑只优化一次放置，与正式评估种子无关；同一拓扑两个负载共用部署。

对照：R-default 与 Helix 放置+RCAPS 路由从 v5_core_supplement 的五种子核心交叉实验复用，先验证执行器和轨迹等价。新增 R-noshare、R-uniform、R-pipelines、R-greedy、R-random 共 5×4×5=100 个 1800 s、零预热、不排空的 CPU 仿真窗口。正式种子 0–4；单集群 350/700、三集群 160/320 token/s。同种子所有方法的 trace SHA256 必须相同。失败原件独立保留。

- R-noshare：独立实现多入口放置验证、目标评估、导出与搜索；只放松首段必须单副本限制，其他容量、链路和完整路径约束不变。采用与原 M2 相同静态目标函数、Beam=64、共用 B0=500 加扩展 B1=500 的评价预算。宽度变化进入初始化，局部邻域沿原搜索定义。多入口不能用原单入口验证器伪装通过。
- R-uniform：三段等层数（余数从末段向前分配），每段同一最大可行副本数；GPU 选择和层分配须满足物理链路、容量、KV 及完整路径，不能只满足总显存。
- R-pipelines：容量比例生成 GPU 不交叠的完整流水线，允许导出的层兼容 DAG 存在跨流水线转换；结构约束是不共享前段。
- R-greedy：按静态剖析得分最快的可行 GPU 建第一条完整链，随后按瓶颈层段顺序利用剩余 GPU 增加副本；每一步均重新验证实际可达性。
- R-random：固定规划随机种子 20261029；在所有硬约束下采样，用与 R-default 相同静态目标比较 1000 次有效候选评价并选最低分。无效提议另计，不占有效评价预算；设置明确的提议上限，若达不到预算，报告实际评价数及原因。

布局生成前冻结优化器版本、资源配置、画像、静态目标、规划随机种子和所有预算。每个布局保存段/边界/副本数、层副本总数、使用 GPU、完整路径数、搜索墙钟、评价数及文件 SHA256。新增在线窗口统一记录 P95 TPOT、P95 TTFT、吞吐、完成率和 GPU 秒/token；只在五个成功配对种子上计算相对 R-default 的均值变化及 df=4 的双侧配对 t 95% CI。若 R-noshare 与 R-default 的差异区间跨零，按原样报告，不修改目标或筛选负载。

已知工程边界：当前 rcaps.v3.placement.validate 强制首段单副本，导出时也只写一个源入口。E1 实现必须在独立目录完成多入口放置和运行时路径验证，不修改正处于 V4 冻结重放阶段的原模块。若多入口在当前模拟器内无法等价执行，应将该项记录为实现受限，而非用单入口结果冒名。

## 预结果可行性诊断（不改变正式选择规则）

两套 C1 物理池的层容量总计均为 152，模型为 80 层。R-uniform 若要求各段同宽且宽度至少 2，则最少需要 2×80=160 层副本，超过总容量；因此需按原定义选择最大可行同宽度 1，并用三等段单链结果作为有标识的退化对照。R-pipelines 若要求至少两条 GPU 不交叠的完整 80 层流水线，同样至少需要 160 层副本，硬约束下不可行；仅该项报告结构不可行，不用共享前段代理冒名。R-noshare 的宽度 (2,1) 实测可行，60 s 多入口执行冒烟的源入口分别为 GPU 0/3，两条路径各分配 12 个请求，见 PROBE_AUDIT.json。该诊断不用于按结果挑选正式布局。
