# E5b 边界诊断批次修订登记

登记时点：原冒烟及其独立失败重放均已终结、正式 80 窗口尚未运行。

原 `smoke/manifest.json` 的 16 个窗口在真正 `conda activate gllm` 环境中运行，13 成功、3 失败。失败键均为长 Prompt 下 Helix+ 的 `No next level node meets scheduling requirement at compute 0!` 断言。三项在 `smoke_failure_replay/` 的独立串行重放中再次出现相同断言。原 `run_e5b.py` 规定冒烟必须 16/16 成功才能登记 `formal/`，因此原正式批次不启动，也不修改原脚本、清单或失败工件。

为核实该边界是否随种子变化，另设 `formal_boundary_diagnostic/`。保留原设计的 16 条件 × seed0–4，共 80 个 1800 s 窗口；不删去冒烟失败条件，不更改负载、部署、轨迹、容量、Prompt 倍数、指标或 7500 token 画像边界。所有窗口在完整激活的 gllm 环境中运行。每个键只做一次原诊断尝试，失败原件保留、后续独立重放。只有 5/5 成功且同轨迹的组报告均值及配对区间；不足 5/5 的组报告成功数、失败类型，不填零。

本批次是看到冒烟失败后登记的**边界诊断**，不能冒称为原预注册正式批次。若 Helix+ 无可接纳节点，其含义只限于本模拟器的部署、准入逻辑和这些请求条件；不把 Python 断言、Windows 原生崩溃或画像越界混作性能测量。所有旧结果与本批次分列。
