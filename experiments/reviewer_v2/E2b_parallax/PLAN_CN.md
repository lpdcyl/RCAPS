# E2b：Parallax phase-1 + 路由的模拟器复现预注册

登记：2026-10-30，生成正式结果前。参考源码固定为 GradientHQ/parallax commit 162354a03234a28cf6e2946e2e0b2203da7c3721，本地快照和许可证见 experiments/v5_parallax/source/。本项仅为 70B 公共离散事件模拟器内复现，不是原版真实后端、成员协议或分布式遥测。

## 固定算法与近似

1. 使用 DynamicProgrammingLayerAllocator 源码的状态、转移和 k²/s*(k) 规则，目标为用容量可行节点构成 GPU 不交叠的完整流水线，先最少阶段再按评分选 k。24 节点容量总计 152 层，模型 80 层，所以 k 最大只能为 1；该资源池无法检验多流水线评分选择。
2. 把公共模拟器 ModelManager.get_max_num_layers 作为节点参数容量，终点也用该容量；由于公共画像没有原系统单独的 embedding/head 参数内存，本项不另扣端点容量，这是明确的近似。由公共拓扑的物理链路、KV 容量、完整覆盖和实际路由检验可行性，不添加不存在的边。
3. 计算能力固定为 1/profile_at(decode_bs2time, 8)，即每层 batch=8 的剖析耗时倒数，不称 TFLOPS。使用 40 次二分的受容量约束水位均衡分层，向下取整后按余数及节点序补足。该换算与原版硬件 TFLOPS 不同，报告单列。
4. 路由沿用 experiments/v5_parallax/evaluate.py 的边界兼容 DAG 与在线 P2 代理，分别使用公共 FIFO 和 shared 执行器，关闭 RCAPS S/T。共享同一新放置和同一工作负载轨迹；路由仅依当前队列。

## 窗口和判定

单集群 350/700、三集群 160/320 token/s，seed0–4，两执行器，共 40 个正式 1800 s 窗口，零预热，不排空；冒烟用每拓扑每执行器 seed100 60 s 共 4 窗口。部署在同拓扑两个负载之间复用，独立于种子和运行结果。先冻结代码、画像、拓扑、部署、轨迹生成器及 Python 环境 SHA256。

每窗口记录 P95 TTFT/TPOT、吞吐、完成率、GPU 秒/token、轨迹和部署哈希及失败原因。仅 5/5 成功的组计算均值；只在轨迹、度量口径和部署满足配对条件时计算 df=4 配对 95% CI。单种子失败原件保留，独立重放另列，绝不填零或覆盖。最终结果须明示单流水线的容量约束与上述模型映射偏差，标题只称“Parallax（模拟器复现）”。
