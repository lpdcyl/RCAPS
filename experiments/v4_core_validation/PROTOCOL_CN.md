# RCAPS 主线收紧后的核心补证协议

登记日期：2026-10-27（Asia/Shanghai）。本轮只检验最终完整系统中的会话持续服务代价与传输分块的额外占用成本，不扩展算法、外部高负载或同边数路径选择。

## 1. 固定条件与结果身份

- 方法为当前完整 RCAPS；每项替换明确记录，不改变 `rcaps/`、`simulator/` 或旧实验源码。
- 同一冻结 Python/依赖/线程配置、原始设备画像和部署；稀疏准入、实时 GPU/链路快照、Decode 优先、同跳合并与会话路径绑定保持不变。
- 默认分块为慢 GPU 间链路、50,000,000 B/s 阈值、4,194,304 B 块长。
- 工作负载种子 0/1/2。到达前缀为 1800 秒，之后无新到达，观察至 5400 秒；未完成请求仍按右删失报告。
- 一次窗口包括完整模型与完整到达轨迹。短窗口仅用于验证新增执行路径，不作为论文结果。
- 最多两个仿真 worker。单窗口失败留档后继续，不自动重试，不覆盖尝试，不根据结果更改参数。

## 2. 会话项独立对照：6 个新窗口

单集群负载 700、三集群负载 320，各种子 0/1/2。从完整 RCAPS 只移除路由代价中的活跃会话计数项，使用现有 `routing_state=no_session`。实时 GPU/链路工作量快照保留；KV 状态本身和固定会话路径不移除。

比较对象为相同轨迹、相同测量窗口的完整 RCAPS。优先复用上一批 `cohort_tail` 的完整系统原始记录，注册时保存其身份和校验值。零干预适配器必须先与原评估器进行精确公共指标等价检查。

## 3. 分块边界占用开销：9 个新窗口

三集群负载 320，种子 0/1/2。固定完整 RCAPS，分别对每个非末尾 Prompt 块增加 1、10、100 ms 的释放前占用开销。取值在正式运行前固定，覆盖多个数量级，不作为测得的硬件参数。零开销完整 RCAPS 与关闭分块的参照使用相同 `cohort_tail` 记录。

成本语义：块的载荷字节完成序列化后，原传输继续持有其已分配的链路、发送 NIC 和接收 NIC 带宽额度，持续指定时延，然后才执行原释放、Decode 优先调度和 Prompt 续传流程。该附加区间没有传输任何新字节，不增加传播时延，不改变载荷或接收条件，不模拟全局 CPU 调度队列。只对实际产生的中间块边界计费。

这是明确的资源占用成本敏感性，不能替代实机软件/协议开销校准。测量将额外占用与序列化字节分别记账，不能把附加等待时间乘带宽误报为新传输字节。若测试范围未出现收益交叉，只报告该范围内结果，不推算一个未经观测的临界值。

## 4. 指标、配对与判定

联合报告请求级 TPOT P95、TTFT P95、输出吞吐、完成率、末端积压、GPU 工作/token、总 GPU 工作和最后完成时刻。保留逐请求记录、实际路径数、Decode 批量、分阶段 GPU 工作、已结算网络等待及末端未结算量。尾部吞吐分母为 5400 秒，不与 1800 秒主表混算。

每种子独立配对，报告单值、均值和样本标准差，不把三个种子自动解释为统计显著。缺失或失败的配对不合成为完整三种子表。只有全部完成且请求/目标输出一致的组用于“相同完成工作量”的比较。

会话项的作用可减弱、无效或退化；开销敏感性同时保留 Decode 收益、Prompt 代价和未完成情况。负结果不触发调参换取优势。

## 5. 工程验证与完成条件

新增路径只做一次必要工程验证：零开销适配器等价、会话项隔离、正开销延迟释放与字节守恒。工程失败保留并仅修复实际代码错误，正式登记后不修改正在运行的源码。

全部 15 个正式窗口终止后执行一次综合核对，区分成功、失败、未尝试、右删失与硬件未完成。输出本目录 `RESULTS_CN.md`、`results.json` 和逐种子表，并更新论文证据状态与写作蓝图。旧实验报告及原始记录不覆盖。完成交付后暂停本聊天的实验监控自动化。
