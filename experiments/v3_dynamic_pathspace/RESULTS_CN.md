# 工作三：动态路径准入开发记录

所有窗口为固定 M2 布局、冻结 M3 选路代价与 tie order、统一实际执行层 KV 全生命周期预约的 CPU 事件仿真。动态准入只改变 M3 可见的边。完整样本和输入哈希保存在 `runs/`；300 秒窗口只用于筛选，不作论文正式结论。

## 第一版 60 秒结构检查

初始规则使用“单请求 Decode 相对典型批”的 154-token 罚项。`runs/smoke/` 中 C1_single 与 C1_multi 均没有新增边被准入或选中，动态候选分别与静态门控逐项相同。因此该版没有实现可检验的动态控制。`runs/smoke_v2/` 是改成相对边际批代价后的新结构检查，单/三集群分别选中 39/4 次新增边。旧窗口没有覆盖或删除。

## 第二版 300 秒配对开发窗口

同种子 100、同请求轨迹，两拓扑零预热、不排空。相对静态门控：

| 条件 | 吞吐静态→动态 | P95 TTFT 静态→动态 | P95 TPOT 静态→动态 | 平均 Decode 批 静态→动态 | GPU 秒/输出 token 静态→动态 | 新增边被选中 | KV 延后 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| C1_single, 700 | 119.853→114.687 | 3.345→3.601 s | 0.532→0.584 s | 5.58→3.13 | 0.0648→0.1100 | 242 | 0/0 |
| C1_multi, 320 | 53.133→53.687 | 5.794→5.570 s | 0.682→0.670 s | 4.49→3.79 | 0.0757→0.0875 | 16 | 0/0 |

C1_single 吞吐约 −4.31%、P95 TPOT 约 +9.96%，超过 `protocol_dev.json` 的 −0.5%/+2% 停止边界；**第二版不进入正式窗口**。C1_multi 的方向虽好，但单集群失败不能被三集群的改善抵消。单集群 Decode 批显著变小、GPU 工作/输出 token 增加，同时吞吐与延迟变差，支持“任意 GPU 队列绕行会破坏批凝聚”的机制解释；它不证明单个因素的精确因果份额。

静态门控在本轮 C1_single 与 C1_multi 的 300 秒重跑，与旧 `v3_gated_pathspace/runs/dev` 的种子 100 窗口在吞吐、TTFT、TPOT、完成率、积压和 trace hash 上逐项一致，且 KV 延后为零，说明统一 KV 保护未改变这两个对照的观测结果。C1_single 静态窗口曾有一次 profiler 的 `list_iterator` 类型异常，重跑成功；失败 JSON 保留。另有一次 C1_multi 动态进程无 Python traceback 退出，单进程重跑成功；不把失败尝试当成有效数据。

下一候选只用**链路压力差**触发新增边，避免以 GPU 等待差为由拆散单集群批次。它是新开发候选，需要独立协议和同轨迹窗口；不得把上表当作正式验证或调参后的成功结果。

## 路径空间机制：直接资源观测

下表为固定布局、同种子 100、300 秒、统一 KV 预约的**开发诊断**。C1_single 的 static 与 canonical 边集相同；C1_multi 另跑了 canonical。链路服务秒/输出 token 是各链路传输服务时间求和后归一化，不是独占链路忙碌时间；dispatch wait 含调度决策和带宽等待，不等同纯链路排队。

| 条件 | 路径空间 | 吞吐 | TPOT P95 s | 平均 Decode 批 | GPU 秒/输出 token | 链路服务秒/输出 token | dispatch wait 秒/到达请求 | 实际路径数 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 单集群 700 | 完整 DAG | 114.337 | 0.573 | 2.91 | 0.1179 | 0.0015 | 0.031 | 168 |
| 单集群 700 | static = canonical | 119.853 | 0.532 | 5.58 | 0.0648 | 0.0022 | 0.029 | 12 |
| 三集群 320 | canonical | 48.623 | 0.771 | 7.19 | 0.0521 | 0.0354 | 12.570 | 3 |
| 三集群 320 | static | 53.133 | 0.682 | 4.49 | 0.0757 | 0.0186 | 9.952 | 8 |
| 三集群 320 | 完整 DAG | 52.930 | 0.675 | 3.07 | 0.1064 | 0.0146 | 9.476 | 19 |

单集群关掉非规范边后，批大小 2.91→5.58，GPU 秒/token 0.1179→0.0648，吞吐与 TPOT 同时改善；在这套固定布局和仿真中，批凝聚是直接可观测的中介。三集群则有相反制约：canonical 的 GPU 工作最低，却把 5 条慢规范边上的累计传输服务时间从 static 的 273.9 秒增到 489.2 秒，dispatch wait 也由 9.95 增到 12.57 秒/到达请求。开放部分绕行边后 TPOT 0.771→0.682，说明必须保留网络逃逸；完整 DAG 进一步减少链路服务却再度增加 GPU 工作。

现有**三种子正式窗口**的同环境 V3 重跑与 static 对照，在 `analysis.json` 中复算：单集群 static 的 GPU 秒/token 平均相对减少 45.98%，链路服务秒/token 增加 45.20%（绝对量很小），P95 TPOT 下降 9.54%；三集群 GPU 秒/token 减少 29.73%，链路服务秒/token 增加 25.62%，P95 TPOT 反而增加 1.81%。这些是逐种子相对变化的算术均值，三个种子不证明统计显著性；正式延迟结论仍以原始窗口和完成率为准。

## 稀疏负载探索

预设的 350 offered token/s 窗口仍有 28–39 个末端积压且完成率仅 0.63–0.73，因此没有把它称为空闲负载。之后按 `protocol_idle.json` 明确标为**事后探索**，在 100 offered token/s 跑同轨迹的 full/static：两者各到达 31 个请求，窗口边界各有 10 个未完成请求；Decode 平均批为 1.07/1.18，单请求批占比 0.94/0.85，最大 GPU 忙碌比例 0.37/0.25。TPOT P95 为 0.3279/0.3312 秒，static 在这个小样本中没有尾延迟收益。固定窗口未排空，因此不能把 10 个未完成请求都解释成容量饱和。

## 判定范围

- **工作三机制可以整体解释**：可用路径空间决定“GPU 批凝聚”与“慢链路绕行”的交换，M3 只在已准入路径上选路。单集群和三集群的反向结果、直接资源指标和去单请求批 2 倍规则的既有正式反事实（`v3_batch1_counterfactual/RESULTS_CN.md`）共同支撑这个解释。
- **新动态门控尚未成为正式贡献**：两版均在预注册开发筛选处停止，没有拿开发种子重命名为正式结果，也没有启动 42 节点扩规模验证。
- **KV 只得到容量保护的局部证据**：所有新配对窗口的容量延后次数均为零；这不排除准入检查曾否决某条候选边，不能把零等待直接等同“KV 完全不影响路径”。单集群完整 DAG 的开发窗口与旧版 V3 在解释器/NumPy 版本和是否启用 KV 保护上不同，应只用本轮同环境配对解释；42 节点高负载的 KV 安全性与少卡比较另见 `v3_cluster42/kv_slice/SUMMARY_CN.md`。
- `report.py` 从原始 JSON 复算 `analysis.json`，校验请求样本数、同条件的 trace hash、输入文件哈希与解释器版本，并核对三集群去批保护的跨解释器重复；窗口 JSON 带布局、物理资源、调度器哈希。三个解释器都曾出现随机访问冲突，需要单独排查。成功窗口的配对与重复检查不等于运行环境稳定，正式新候选因此尚未启动。
