# RCAPS V2 递进式方法消融

顺序为基础方案 → A（资源感知放置）→ A+B（自适应共享复制）→ A+B+C（动态调度）。基础方案和 A 使用相同的一张共享 A100、12 层前缀、双后缀约束与固定合法路径轮转；A+B 和完整 V2 使用字节相同的自适应布局。前三阶段共用 KV 容量安全准入，以仿真轨迹给定的目标输出长度作为预留上界，不以实时 GPU/链路负担改变轮转路径。真实服务需要请求声明的最大长度或其他预留上界。

70B、两种原始 24-GPU 拓扑，single/multi 负载分别为 700/320 offered token/s；正式种子 0/1/2，1800 秒零预热且不排空尾部。

绝对值为三个正式窗口指标的均值 ± 样本标准差；P95 是三个种子各自 P95 的均值，并非合并请求重算。增益先在每个种子内配对计算，再取均值 ± 样本标准差。吞吐、完成率越高越好；TTFT、TPOT、积压越低越好；负增益如实表示退化。

## 归因边界

A 检验同一固定结构与静态调度下，容量规则和完整 V2 资源感知放置流程的差别；它包含候选构造、设备排序、层分配与事件图评分，不单独归因于某个分数项。
B 检验同一 V2 放置评价与静态调度下，自适应共享范围、设备分组、层边界与复制结构的联合作用。
C 检验同一最终布局下，V2 在线 DAG 选路与传输合并的整体作用。A+B 的保守 KV 准入规则在六个正式窗口均未触发，实际执行记录与原静态对照一致；仍不能将差额单独归因于选路或传输合并。
未加 KV 容量保护的固定结构静态对照在正式种子 1 触发模拟器容量断言；失败日志保留在 attempts_pre_kv_guard/，未计算完整窗口指标。
各步差额是不同条件下的增量，不能直接相加。种子 1 曾参与早期开发；三个种子只描述配对波动，不作显著性或真实集群性能声明。
